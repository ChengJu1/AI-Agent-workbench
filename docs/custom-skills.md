# 自定义 Skill

Skill 用于保存可复用的工作方法。当前支持网页创建与编辑、单文件 `SKILL.md` 导入和导出、Markdown 预览、版本记录，以及新建或已有 Agent 的绑定。

## 页面使用

1. 打开工作台侧栏的 **Skill 管理**。
2. 点击 **新建 Skill**，填写名称、用途与适用场景、工作步骤与规则；或点击 **导入 SKILL.md**。
3. 导入只填入草稿，不会自动保存或绑定。检查正文后点击 **保存 Skill**。
4. 在创建 Agent 时选择 Skill，或通过已有 Agent 顶栏的 **绑定 Skill** 调整配置。在 **使用版本** 中选择具体版本，再保存绑定。管理窗口也提供 **绑定到当前 Agent** 入口。
   选择 v2 后将一直读取 v2；发布 v3 不会自动升级，需要手动切到 v3 并保存。不同 Agent 可以绑定同一 Skill 的不同版本。
5. 下一轮对话只提供已绑定 Skill 的名称、用途与版本目录；目录过大时只提示数量，由模型先调用 `search_skills` 按关键词搜索或分页浏览。模型选择相关 Skill 后，通过只读 `load_skill` 工具读取完整正文；普通聊天不必读取。
6. 回答下方显示实际读取的 Skill 名称和版本；未读取时明确显示“本轮未读取 Skill”，刷新后保留。旧版预载记录单独标为“预载 Skill（旧记录）”。

Skill 预览与聊天回答共用 Markdown 排版，支持标题、嵌套列表、只读任务清单、引用、表格、代码块、删除线与链接。表格优先适应容器宽度，窄屏保留横向滚动；长代码在代码块内独立滚动，正文正常换行。

仅绑定 Skill、不连接 MCP 或知识库，也可以创建 Agent。这类 Agent 可以处理用户提供的文本，但没有因此获得文件读取、命令执行或项目巡检工具。

仓库提供一个可导入的 [需求拆解示例](examples/skills/requirements-breakdown/SKILL.md)。它要求保留需求出处、列出验收条件，在没有检查证据时将任务标为待验证。该示例用于对话中的文本整理，不代表项目 TODO 或自动巡检模块已经实现。

## 文件格式与限制

文件为 UTF-8 编码的 Markdown，顶部使用 YAML 元信息：

```markdown
---
name: 需求拆解
description: 将项目说明整理成有出处、有验收条件的任务。
---

## 工作步骤
1. 明确项目范围，提取需求原句。
2. 列出任务、验收条件与需要的证据。
3. 没有检查证据时标为待验证。
```

- 名称最多 100 字符、用途最多 1000 字符、正文最多 30000 字符；均不能为空。
- 上传文件最大 128 KB，元信息最多 8192 字符。支持普通 YAML 字符串和多行说明；不接受 YAML 对象标签或锚点。
- 只读取 `name`、`description` 和 Markdown 正文；其他元信息字段会在导入时提示未启用。
- 本版不加载目录包、脚本、附件或引用文件，不执行 Markdown 中的代码，不通过 `allowed-tools` 等字段开放工具。
- 不限制每个 Agent 的绑定数量，也不限制绑定正文的总长；重复 ID、无效版本仍会被拒绝。绑定不会预先加载全部正文。实际读取遵循下述本轮预算。
- 同名 Skill 不能重复创建；导入已有名称时，可改名另存，或在已有条目上编辑正文。

## 目录与实际读取预算

- 绑定面板支持按名称和用途筛选、仅看已选以及“显示更多”。初始显示 25 项，点击后继续显示；这是列表展示数量，不是绑定上限。筛选或翻页不会移除已选版本。
- 小目录直接提供名称、用途和版本。目录 JSON 超过 12000 字符时，初始提示改为搜索说明，不把全部 ID 转移到工具参数枚举中。
- `search_skills` 仅查询本轮固定且仍有效的绑定，按名称和用途进行关键词匹配。多关键词用空格分隔；无匹配时可改用更短关键词，空查询用于分页浏览。每次最多 20 条且响应不超过 12000 字符，用 `next_offset` 继续查询，不截断条目。搜索结果不含正文，也不计为已读取 Skill。
- 默认每轮最多成功返回 80000 字符的 Skill 正文，可通过后端 `.env` 中的 `WORKBENCH_SKILL_READ_BUDGET_CHARS` 设置任意正整数，重启后端生效。Compose 运行时修改环境文件后需重新创建后端容器以加载新环境配置。这是应用的可配置预算，不是模型的上下文上限或 Token 数。
- 只在成功读取正文时扣减，重复读取全文也会重复扣减；审计失败、无效 ID 和预算不足的读取不扣减。并发读取共享同一预算。下一轮重新计量。
- 超预算会明确拒绝该次读取并说明剩余量，完整正文既不返回也不截断，记录中只保留成功读取的 Skill。模型应缩小当前任务或在下一轮继续。
- 该预算只覆盖本轮新增的 Skill 正文，不包含目录元信息、聊天内容或历史工具结果；不会清空历史上下文，也不能保证整个会话永远不超过模型上下文容量。

## 版本与生效范围

- 首次保存为 v1。名称、说明或正文变化后增加版本；内容未变时不重复生成版本。
- 每个 Agent 保存具体的 Skill ID 与版本；本轮开始时读取用户固定选择的版本快照，初始提示仅包含用途目录或目录搜索说明。正文、名称和用途都来自该版本，不自动替换为最新版。
- 切换版本从下一轮生效。读取工具只允许读取本轮目录内且仍与当前 Agent 绑定的相同版本；中途切换或解除绑定后，未执行的旧版本读取会被拒绝，提示下一轮重试。
- 管理页的 **版本记录 → 查看版本** 只预览历史正文；**绑定 Skill → 使用版本 → 保存绑定** 才会改变 Agent 实际使用的版本。
- 升级时，旧绑定固定为升级当时正在使用的版本；之后重启或发布新版本都不会再自动升级绑定。
- 历史回答保留当轮实际读取的 Skill ID、名称和版本；不是根据绑定列表或模型自述推断使用情况。完整旧正文保存在独立版本表，可以在管理页的 **版本记录** 中查看并导出。
- 导出历史版本时输出正在查看的版本；导出后在其他工作台导入，会由目标工作台重新分配 ID 和版本。
- 并发编辑使用版本校验，过期编辑不会覆盖较新的保存。出现冲突时，先保留需要的文本，放弃草稿后重新打开最新记录。
- 取消全部绑定只移除自定义 Skill，内置 Agent 的原有规则仍保留。
- 正文只在模型调用读取工具后作为工具结果进入上下文，不做自动摘要或截断。读取过的工具结果可能继续存在于会话历史中；按需读取不代表自动清除旧上下文。内置 Agent 的原有文本规则仍按原方式加载。
- 读取记录表示工具成功返回了对应正文，不保证模型严格遵守全部要求，也不代表已经执行了 Skill 描述的检查。每轮相关任务要求重新读取当前版本，以便追溯。
- 每次读取写入审计记录，记录版本引用而不重复保存正文；异常或回复中断时仍保留已经完成的读取记录。

工具白名单、知识库绑定范围和审批流程继续由后端控制；Skill 不能授予额外权限。Skill、绑定及版本保存在当前工作台数据库，推送代码不会同步这些运行数据。本版暂不提供 Skill 删除、将库中最新正文回退为旧版本、未绑定 Skill 的全库自动发现或项目级绑定；Agent 可以自由切换并使用已有的历史版本。

## 接口与验证

| 接口 | 作用 |
| --- | --- |
| `GET /api/skills` | 查询当前 Skill |
| `POST /api/skills` | 创建 Skill |
| `POST /api/skills/import-preview` | 解析文件，返回待保存草稿及未启用字段 |
| `PUT /api/skills/{id}` | 带 `expected_version` 更新 Skill |
| `GET /api/skills/{id}/versions` | 查询历史版本正文 |
| `GET /api/agents/{id}/skills` | 查询绑定 |
| `PUT /api/agents/{id}/skills` | 原子替换固定版本绑定，参数为 `skill_ids` 和 `skill_versions` |

绑定请求示例：`{"skill_ids": ["skill_example"], "skill_versions": {"skill_example": 2}}`。创建 Agent 使用相同字段。版本不存在时返回 404 且不改变原绑定；版本必须为正整数，只能为已选择的 Skill 指定版本。旧调用方不传版本时，在保存时固定为当时的最新版，后续不会自动跟随。

内部工具为 `mcp__workbench_skills__search_skills`（`query`、`limit`、`offset`）与 `mcp__workbench_skills__load_skill`（`skill_id`）。正文读取结果附带 `budget`，说明字符预算、已用量与剩余量。这些工具由后端按 Agent 绑定注册，不需要用户额外配置 MCP 连接，也不授予文件或命令执行权限。`workbench_skills` 与 `workbench_knowledge` 为保留连接名。

数据库启动时只增加 Skill、版本与绑定表，旧 Agent 和历史消息保持兼容。升级后安装最新 `backend/requirements.txt` 并重启后端，前端的新入口才能连接新接口。

本次验证包括版本不可变、过期编辑保护、输入与导入边界、绑定失败回滚、目录不含正文、真实内部 MCP 协议读取、轮次快照、解除绑定拦截、读取审计失败保护、中断后的读取记录保存和历史恢复。前端验证按需读取、未读取和旧预载记录的区别。页面的创建、导入导出、编辑和版本查看沿用此前验收结果。

真实页面验收使用不含私人资料的虚构待办项目：同一会话先打招呼，显示“本轮未读取 Skill”；随后提出需求拆解任务，模型实际调用读取工具，显示“本轮按需读取 需求拆解 · v2”，刷新后恢复两个状态。后端 144 项、前端 47 项测试及生产构建通过。

固定版本验证：后端 148 项、前端 49 项测试通过，生产构建通过。覆盖旧数据库迁移、重启后保留版本、Agent 独立选择、v1/v2/v3 双向切换、选中版本的正文长度限制、非法版本失败回滚、内部 MCP 实际返回的正文与会话历史版本。浏览器验证已有 Agent 切换并保存旧版本、重新打开后保留选择，再恢复原 v2；未新增外部模型请求。

取消绑定上限验证：后端 154 项、前端 50 项测试与生产构建通过。临时测试库验证 8 个 Skill、合计 240000 字符正常绑定，超过 5 个短 Skill 可在同一轮读取；验证实际读取预算、重复读取、并发预算检查、可配置预算、大目录分页、范围与版本校验、超过 5 项的流事件及历史恢复。真实内部 MCP 协议验证搜索结果不含正文、只在读取后记录版本。页面验证新筛选入口、无匹配时的已选计数与保存后 v2 绑定仍保留。本次未新增外部模型请求。
