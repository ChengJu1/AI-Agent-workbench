## 1. 方案结论

Workbench 的目标是让用户通过自然语言创建能够完成实际任务的 Agent。用户提供目标、资料和授权范围后，Agent 应能规划步骤、调用工具、处理动态页面、展示实际结果，并在用户确认后完成最终提交，随后记录和跟踪业务状态。

招聘投递用于验证这套能力能否跨网站工作。平台模型使用“任务、对象、资料、权限、步骤、审批、证据、跟踪”等通用概念；岗位、简历、教育经历等属于业务配置。相同底座应能支持报名、资料报送、工单办理和项目巡检。

核心设计决定：

1. 平台构建主 Agent 优先发现、选择和组合已有工具与 Skill，确实缺能力时才生成独立 MCP 扩展。
2. 浏览器、文件、邮箱、凭证和持久化能力由平台维护，生成代码通过受控接口使用；不为每个业务 Agent 重写基础设施。
3. 业务 Agent 负责分析与决策，平台运行器负责权限、进度、审批、互斥、恢复和审计。
4. 首次向网站发送资料前授权；最终业务提交单独审阅。填写和上传可能立即发送资料，不能只在最后一个按钮前确认。
5. 以实际网页值和回执判定结果，区分“动作已执行”“提交已确认”和“业务已办结”。
6. 默认单 Agent；团队协作是可选能力，由用户审阅收益、成本和权限后启用。
7. 敏感资料采用独立本地凭证库；保存位置、模型使用范围和对外发送范围分别控制。
8. 先交付可靠的单 Agent 闭环，再扩展邮箱、长期任务、生成连接器和团队运行。

## 2. 目标、范围与当前基线

### 2.1 用户希望完成的事情

用户可以输入目标网站、目标对象或筛选条件，选择资料版本和隐私设置，决定是否允许团队协作。平台创建或选择合适的业务 Agent，展示所需能力和权限。

执行中由 Agent 完成可支持的页面读取、资料分析、字段填写、日期选择和文件上传。登录验证码可通过获批邮箱连接器协助处理；需要本人验证的环节进入接手流程。填写后展示真实预览与字段对照，由用户拍板是否最终提交。提交后核对回执、登记台账，并在用户启用后跟踪状态。

用户不应因为页面较大、按钮位于 iframe、或流程中出现常规下拉框而被反复要求手动完成整份任务。

### 2.2 第一版范围

- 优先本机个人工作区，浏览器使用对话专用配置。
- 保留现有 React、FastAPI、Claude Agent SDK、SQLite 和官方 Playwright MCP 接入。
- 支持用户指定的网站与对象；岗位搜索可作为前置可选步骤。
- 最终提交由用户审阅确认；未知结果先核对，不自动重投。
- 跟踪只读，默认暂停，启用后按计划检查。
- 未覆盖的控件明确报告具体限制，保留已完成进度。

### 2.3 本轮不承诺的能力

- 所有网站、验证码、SSO 和控件均可自动完成。
- 通过图形验证码识别、规避站点验证或解除网站安全限制完成登录。
- 平台获批一次后可以访问任意邮箱、文件和网站。
- 依靠网站外部调用实现严格的全局“恰好提交一次”。
- 当前个人工作区已经具备可公开部署的多租户隔离。
- 用户关闭电脑后，本机浏览器任务仍能持续运行。

状态基线以 2026-10-20 工作区代码和已有验收记录为准。合成验收通过只证明对应链路成立。

## 3. 平台角色与通用概念

### 3.1 角色职责

| 角色 | 职责 | 约束 |
|---|---|---|
| 用户 | 提供目标和资料、选择权限与保存策略、处理本人验证、批准最终提交 | 可以暂停、撤销和取消后续执行 |
| 平台构建主 Agent | 分析需求、检索已有能力、创建业务 Agent、提出 Skill/MCP/团队方案 | 不直接授予自己或生成包额外权限 |
| 业务 Agent | 规划具体任务、理解页面、映射资料、提出操作、核对结果 | 使用固定版本的能力与明确的数据范围 |
| 副 Agent | 完成范围明确的检索、解析或复核任务 | 不自动继承主 Agent 的全部资料和凭证 |
| 平台运行器 | 维护任务状态、权限和审批、执行锁、检查点、日志、恢复 | 关键约束在服务端执行，不能只写进 Prompt |
| MCP 连接器 | 提供浏览器、文件、邮箱或外部系统操作 | 每次调用校验资源范围及操作语义 |
| 资料/凭证代理 | 将获批的资料引用转换为具体工具输入 | 敏感原文尽量不进入模型上下文或日志 |

### 3.2 通用业务对象

平台将一个申请、工单或巡检对象表示为业务对象。招聘场景的对象可由“网站、账号别名、岗位 ID、招聘批次”识别。

每个对象关联：

- 任务目标和允许的完成条件；
- 使用的资料及附件版本；
- 计划与已执行步骤；
- 授权、审批和证据；
- 当前业务状态及状态依据；
- 可选的后续只读跟踪。

岗位状态不写死为平台任务状态。招聘、报名和工单可以配置各自的业务状态规则。

### 3.3 Skill、MCP 和任务模板的区别

| 类型 | 表达的内容 | 示例 |
|---|---|---|
| Skill | 可复用的工作方法与判断规则 | 如何核对教育经历、如何避免重复申请 |
| MCP 工具 | 可执行的动作和读取能力 | 查页面、选日期、上传指定版本文件 |
| 任务模板 | 某类任务的阶段、输入、完成条件 | 申请办理、资料报送、只读巡检 |
| 站点适配器 | 某种站点/控件结构的已验证操作方式 | 年月区间控件、分步表单的读取与验证 |
| Agent 配置 | 本任务使用哪些方法、工具和资料 | 招聘助手绑定所选 Skill、文件与浏览器能力 |

## 4. 总体架构

~~~mermaid
flowchart TB
    U[用户与任务前端] --> B[平台构建主 Agent]
    B --> REG[能力目录与版本注册表]
    B --> A[业务 Agent]
    B --> EXT[扩展生成与隔离验证]
    EXT --> REVIEW[用户审阅权限与启用]
    REVIEW --> REG
    A --> RUN[任务运行器]
    A --> TEAM[可选团队协调器]
    TEAM --> RUN
    RUN --> POLICY[权限与审批服务]
    RUN --> STATE[任务状态与检查点]
    RUN --> BROKER[受控工具与资料代理]
    BROKER --> WEB[浏览器 MCP]
    BROKER --> FILE[文件连接器]
    BROKER --> MAIL[邮箱连接器]
    BROKER --> OTHER[其他独立 MCP]
    BROKER --> VAULT[本地加密资料与凭证库]
    RUN --> EVIDENCE[证据与执行日志]
    RUN --> TRACK[台账与只读跟踪]
~~~

### 4.1 连接器组织方式

可以连接多个独立 MCP server。平台统一管理能力目录、权限、版本和审计，但连接器不必集中为一个不断增长的业务 MCP。

- 浏览器连接器维护稳定页面操作。
- 文件连接器维护文件读取和版本。
- 邮箱连接器维护认证与受限读取。
- 外部业务系统使用各自连接器。
- 生成能力包按包和版本独立运行，固定到对应 Agent。

MCP 提供工具与上下文交互协议，任务编排和业务恢复由 Workbench 实现，参见 [MCP 架构说明](https://modelcontextprotocol.io/docs/learn/architecture)。

### 4.2 模型与执行层的边界

模型输出结构化计划，不能直接把自然语言“我已完成”写成权威执行结果。运行器校验计划后，由工具执行并返回结构化结果和证据。

工具结果至少区分：

- 操作没有开始；
- 操作已执行，业务结果待核对；
- 操作部分完成；
- 结果未知，需要核对；
- 已取得与对象匹配的业务回执。

网页、邮件、附件和副 Agent 返回的内容都属于不可信资料，不能自行扩大工具权限或修改审批规则。

## 5. 用户流程与权限确认

### 5.1 创建与启动

1. 用户描述目标，输入网站/对象或筛选条件，选择资料和附件。
2. 构建助手检查可复用 Agent、Skill、连接器和任务模板。
3. 展示能力方案、缺失信息、预计步骤、授权范围和保存策略。
4. 用户选择单 Agent 或审阅团队方案。
5. 缺少能力时展示扩展提案及验证结果，启用后固定版本。
6. 创建独立任务 ID。聊天会话关联该任务，但聊天不承担唯一状态存储。
7. 开始读取目标页面，必要时进入登录或本人验证流程。

### 5.2 执行闭环

~~~mermaid
flowchart LR
    G[目标与资料] --> P[计划与任务授权]
    P --> R[读取页面]
    R --> L{需要认证?}
    L -->|邮箱流程已授权| M[查找本次验证码并验证登录]
    L -->|需本人处理| H[人工接手]
    L -->|无需认证| F[字段映射与操作准备]
    M --> F
    H --> R
    F --> W[填写或上传]
    W --> V[读回与差异校验]
    V -->|缺失或不一致| F
    V --> C[用户最终审阅]
    C --> S[提交一次]
    S --> E[核对回执]
    E --> T[台账与可选跟踪]
~~~

### 5.3 两层授权

**任务授权**应明确：

- 允许访问的网站、连接器和账号别名；
- 允许发送的资料字段及附件版本；
- 允许执行的操作类别；
- 任务对象、有效期、预算和数量上限；
- 是否允许模型处理这些资料；
- 是否允许邮箱验证或团队协作。

用户明确授予任务范围后，普通字段填写、控件展开和获批文件上传可以由 Agent 连续完成。执行层仍逐步校验范围，不再要求用户确认每个普通字段。当前逐批审批实现应保留，待任务授权模块验收后才引入此模式。

**最终提交审批**展示目标对象、实际填写值、附件、差异和提交含义，用户点击后只允许对应的一次提交尝试。

以下变化需要补充审阅：

- 新增接收网站、账号或连接器；
- 新增资料字段、敏感字段或附件版本；
- 原计划中的“保存草稿”实际会变成申请提交；
- 网站要求接受新的条款或执行超出任务授权的操作。

站点可能在填写、上传时自动保存。首次资料发送必须已有授权。若选择文件本身就构成最终申请，则将该上传动作升级为最终提交审批，不能假设所有网站都有独立提交按钮。

## 6. 页面读取与复杂控件

### 6.1 页面完整性

要求提供“完整可访问内容＋有界返回”，而不是一次把全部 HTML 塞进模型上下文。

- 保留当前完整快照与全部真实元素引用。
- 返回快照编号、采集时间、总字符数、总元素数和下一页位置。
- 支持同一快照的正文分页、控件分页和关键词查找。
- 支持 iframe、已有标签及可访问的动态内容。
- 滚动或展开动态区域属于明确页面动作；加载后产生新快照并标记范围。
- 对虚拟列表区分“已加载部分”和“全部记录”，不伪称已读全量。
- DOM 不足时可提供截图/OCR 辅助识别；无法确认目标时不给可执行引用。

“完整阅读”不等于突破权限、取得服务器未返回的资料或绕过网站验证。

### 6.2 观察与操作原语

下列是逻辑能力，具体工具命名在实现时确定：

| 能力 | 输入 | 输出与检查 |
|---|---|---|
| observe/read | 会话、标签、可选已有快照 | 页面状态、内容片段、真实引用和分页信息 |
| find | 快照、字段名/语义/可见文本 | 候选控件、上下文、歧义和匹配依据 |
| inspect | 当前控件引用 | 类型、选项、约束、禁用状态及归属 |
| prepare | 快照、资料引用、操作列表 | 计划、资料来源、可能的数据发送和预期后置条件 |
| apply | 已获批计划或任务授权下的步骤 | 已完成步骤、实际结果、错误分类 |
| verify | 当前页面、预期值与完成条件 | 实际值、差异、证据和是否需要处理 |

读取本身不执行业务提交；滚动、展开、选择和输入按真实行为归类，不以 GET/POST 简单判断业务写入。

### 6.3 控件适配矩阵

| 控件 | 处理方式 | 验证方式 |
|---|---|---|
| 原生输入框/文本域 | 按类型和长度约束填写 | 读回值及页面校验错误 |
| 原生 select | 核对真实选项后选择 | 读回选中值与标签 |
| 自定义下拉框 | 展开、读取新选项、选择，分阶段读取 | 核对选中显示和隐藏表单状态 |
| 单选/多选 | 核对当前状态，仅在需要时改变 | 读回 checked/selected |
| 日期、年月 | 使用语义日期适配器或可验证的分步选择 | 核对年月日、格式与时区含义 |
| 日期区间 | 开始/结束分别绑定，支持“至今” | 起止顺序、精度和“至今”状态 |
| 地区级联 | 逐级选择并读取后续选项 | 省/市/区或国家/城市完整路径 |
| 多段经历 | 添加行、绑定记录和该行控件 | 行数、顺序及每段记录完整性 |
| 上传/拖拽区域 | 定位真实上传入口或 file input | 文件名、解析状态与接收回执 |
| iframe 内控件 | 使用框架提供的真实帧引用 | 当前帧、控件和目标对象匹配 |

控件适配优先覆盖通用结构，必要时追加带版本和回归样例的站点适配器。发现未知控件时保存页面依据和能力缺口，不把不可验证的 CSS 猜测直接用于执行。

### 6.4 变化与快照有效性

焦点、光标、样式类名或观察编号变化不应单独导致计划失败。网址、目标控件、正文关键内容、字段值、选项、禁用状态和文件选择变化则应重新核对。

分页和搜索已有快照不改变其编号。新读页面、手动接手/交回、切换标签或执行消费后，旧审批按规则失效。不能为恢复读取自动关闭或刷新用户已登录的填写页。

## 7. 资料解析、字段映射与文件上传

### 7.1 通用资料模型

原始文件与结构化事实分开保存。每条事实至少有值、来源、版本、精度、敏感等级和用户确认状态。

~~~yaml
profile_version: profile_example_v1
facts:
  - field: education[0].start_date
    value: "2022-09"
    precision: month
    source:
      file_id: file_example
      file_version: 1
      section: 教育经历
    sensitivity: personal
    review_state: needs_review
~~~

该示例为拟议数据结构，不是当前可直接调用的 API。

不将缺少的信息当作空字符串直接提交。区分未提供、不适用、解析失败和用户明确留空。模型推断的事实须标记，不冒充原文。

### 7.2 字段映射

每个网页字段记录：

- 所属业务对象、页面和经历行；
- 当前真实控件引用与语义名称；
- 来源资料、来源版本和原值；
- 转换规则与拟填写值；
- 必填性、格式、可选项及约束；
- 是否推断、是否缺失、是否需用户补充；
- 执行后实际值和验证结果。

例如：资料仅有“2022.09—2024.06”，网站要求年月时可转换格式；要求具体日时需补充，不默认为每月 1 日。学校、专业、学历或城市选项无法精确匹配时，展示候选差异后询问。

### 7.3 上传流程

1. 核对当前会话文件、版本、哈希、大小和格式。
2. 找到真实上传入口，核对对应站点和对象。
3. 依据已有任务授权或本批审批确认发送文件。
4. 由文件代理提供获批版本，执行浏览器选择与上传。
5. 核对文件名、网站接收状态及解析状态。
6. 自动解析后重新读取字段，逐项校验，不默认解析正确。
7. 未明确上传成功时保持待核对状态，禁止直接进入最终提交。

上传副本应保留到浏览器不再需要读取时再清理，避免选择后立即删除导致延迟提交失败。清理策略受当前任务保存策略和浏览器生命周期约束。

### 7.4 资料更新

文件内容变化、用户更正事实或切换简历版本时创建新版本。依赖旧版本的未执行计划需要重新核对或失效。

本机文件丢失/移动时只询问该文件的新位置或替代文件，不扫描用户目录。已执行步骤保留原版本证据，不能被新版本改写。

## 8. 登录、邮箱与验证码

### 8.1 邮箱连接器

优先采用邮箱服务商支持的 OAuth 或其他正式授权机制。首次连接由用户完成授权，凭证由专用凭证服务保管，业务 Agent 只取得连接引用。

权限界面区分：

- 服务商实际授予的权限；
- 平台本次任务施加的读取过滤；
- 允许使用的目标网站与验证码用途；
- 授权有效期和撤销入口。

例如 Gmail 的 gmail.readonly 允许读取邮件和设置，并非服务商级的“只读验证码”。发件人和时间范围过滤属于平台额外约束，应如实显示。参见 [Gmail API 权限范围](https://developers.google.com/workspace/gmail/api/auth/scopes)。

### 8.2 验证码请求绑定

每次验证码读取必须关联一条仍有效的认证请求：

- 指定邮箱连接和接收账号；
- 用户选定站点及认证目的；
- 发起时间、过期时间和已知请求标识；
- 预期发件来源及验证模板；
- 允许的查询次数、等待时间和失败处理。

不得把邮件中任意数字或过往验证码用于当前登录。邮件内容不能指挥 Agent 改变网站、发送文件或扩展权限。

凭证代理将匹配结果用于该请求；日志只保留匹配/验证结果及脱敏关联标识。验证码完成使用或过期后从临时缓存清除，不作为长期个人资料保存。

### 8.3 登录状态验证与人工接手

验证码输入成功不等于登录成功。登录后须核对当前页面账号、站点和目标对象。

遇到图形验证码、设备确认、扫码验证或需要本人处理的认证，任务进入等待用户状态。用户接手时其他 Agent 不读写同一浏览器；交回后核对现场，不重放登录、上传或提交。

密码、OAuth token 和一次性验证码不进入普通聊天、Skill、生成代码和诊断日志。浏览器专用配置和凭证库均应受本机访问控制。

## 9. 任务状态、执行与恢复

### 9.1 分开表达三类状态

| 层级 | 表达内容 | 示例 |
|---|---|---|
| Run 状态 | 平台任务能否继续运行 | running、waiting_user、waiting_approval、blocked |
| Step 状态 | 某次具体操作的执行结果 | planned、running、succeeded、failed、uncertain |
| 业务对象状态 | 外部系统当前进度 | 已提交、筛选中、已结束、未知 |

一次投递任务可以提交成功并结束执行，而招聘对象仍处于“筛选中”，后续跟踪独立运行。

### 9.2 建议 Run 状态

| 状态 | 含义与后续 |
|---|---|
| draft | 用户目标或输入尚未确认 |
| queued | 已入持久队列，等待获得执行资源 |
| running | 正在规划、读取、准备或执行 |
| waiting_user | 等待补充信息或本人认证 |
| waiting_approval | 等待明确操作或最终提交审批 |
| paused | 用户主动暂停，保留检查点 |
| reconciling | 重启或响应丢失后，核对实际执行结果 |
| blocked | 确认存在能力/权限/站点问题，保存原因与恢复入口 |
| succeeded | 达到本任务声明的完成条件并有证据 |
| failed | 不可继续的执行失败，保存已发生的影响 |
| cancelled | 用户取消后续执行；已发送的资料不会自动撤回 |

另用 phase 表示 read、authenticate、map、fill、review、commit、verify 等阶段，避免将所有阶段组合为大量状态。

### 9.3 检查点

在重要步骤前后保存：

- 固定版本的计划、Agent、Skill 和连接器；
- 对象、资料和文件版本；
- 当前步骤及完成情况；
- 最近可核对的页面/标签位置；
- 授权、审批与失效条件；
- 已发起外部操作、结果和证据引用；
- 未确定结果、恢复建议和所需用户操作。

检查点不保存可跨重启复用的 DOM 引用或旧审批权限。恢复必须重新观察实际页面。

### 9.4 写入可靠性与防重复

本地数据库事务不能与外部网站提交形成同一原子事务。设计目标是“先持久化意图、执行互斥、提交后核对、结果不明不重投”，不声称所有网站都能严格恰好执行一次。

建议过程：

1. 生成业务防重标识，查已有申请、执行记录和未知结果。
2. 原子认领步骤并取得浏览器租约。
3. 持久化发送意图、审批摘要及唯一尝试编号。
4. 校验当前对象、账号、页面、资料版本与授权。
5. 发起一次操作；支持业务幂等键的网站使用对应机制。
6. 保存返回结果，读取回执核对。
7. 超时或崩溃时进入 reconciling，先查询当前页面/历史记录。
8. 无法判断结果时保持 uncertain，展示依据，不自动再次提交。

资源租约过期只表示执行者可能失联，不证明外部动作没有发生。新 worker 应先核对已有发送意图；旧 worker 的迟到结果按尝试编号和修订号归档，不能覆盖新状态，也不能因租约重领而重复提交。

招聘对象的防重标识建议包含站点、账号别名、岗位 ID 和招聘批次。不要将简历版本作为“可再次提交”的唯一依据，否则换一版简历会绕过防重。

### 9.5 暂停、取消与错误分类

- 暂停发生在安全检查点；无法中断的请求先核对结果。
- 取消停止未来操作，与向网站撤回申请是两个不同动作。
- 页面引用过期可重新读取；不得自动重放可能已经发生的写入。
- 邮箱授权失效、资料缺失、控件不支持、账号错误、网络失败、结果未知分别展示。
- 达到步骤、时间、费用或重试预算后暂停并解释，不无限循环。

## 10. 审批与证据

### 10.1 审批绑定内容

审批至少绑定：

- 用户/工作区、任务、对象和账号；
- 操作语义、接收网站/已授权服务和资料类别；
- 具体提交摘要、附件版本与哈希；
- 计划修订、相关页面状态及有效期；
- 执行次数和一次性提交尝试标识。

审批不能由模型声称“用户已同意”代替。服务端保存用户实际决策并采用条件更新认领，重复点击不重复执行。

### 10.2 最终审阅

界面展示来源资料、当前网页实际值、缺失项、转换/推断项、目标对象、账号、文件版本和提交含义。预览应基于填后读取结果，不能只是计划中的拟填写值。

用户修改资料或网页后重新比较相关字段。影响提交含义或资料的变化需要重新审阅；纯焦点或样式变化不要求重新走完整确认。

### 10.3 完成证据

优先使用与业务对象匹配的提交编号、站点回执、申请历史记录或用户明确提供的回执。截图可以辅助，但不能仅以一个“成功”关键词认定对应对象成功。

页面正文、截图、字段对照和回执均标记采集时间及对象。失效或历史画面明确提示，读不到新画面时不当作最新状态。

## 11. 隐私、凭证与数据生命周期

### 11.1 三个独立选择

用户分别决定：

1. 数据是否长期保存在本机；
2. 哪些数据允许发送给所选模型服务；
3. 哪些数据允许发送给目标网站。

本地保存不等于本地处理。解析后的简历若返回给云端模型，相关内容就会发送至模型服务。拒绝外发时，使用本地规则/本地模型或本人补充；不能在拒绝后静默使用云端模型。

### 11.2 保存策略

| 数据 | 可选策略 | 建议默认 |
|---|---|---|
| 简历原文件 | 仅本次、保留指定版本、任务结束删除 | 用户在首次导入时选择 |
| 结构化普通资料 | 仅本次、保存档案、单字段删除 | 先审阅再保存 |
| 身份证等敏感资料 | 本地加密、逐站点授权使用 | 不主动收集，按需添加 |
| 邮箱账号与授权凭证 | 保存连接、临时连接、撤销授权 | 使用独立凭证库 |
| 一次性验证码 | 请求生命周期内临时缓存 | 使用后或过期清除 |
| 台账 | 不持久化、保存摘要、保留完整证据 | 明确说明对恢复/跟踪的影响 |
| 执行日志 | 不持久化、脱敏摘要、详细记录 | 脱敏摘要 |
| 截图与页面证据 | 不保存、按次选择、按期限保留 | 涉敏画面先遮盖或不保存 |

“不持久化”模式下，任务运行期仍需短暂维护状态；应用退出后不保证恢复。只读长期跟踪需要最少对象信息和任务定义，不同意保存时不启用持久跟踪。

### 11.3 敏感值代理

Agent 使用 profile.identity_number、credential.connection_id 等引用。审批界面显示字段类别及掩码，工具执行时由本地代理读取获批值并填写，工具返回只含掩码和结果。

避免模型先读取完整身份证再自行在日志里遮盖。原始敏感值不得写入 Prompt、Skill、生成包测试样例、普通审批 JSON 或诊断异常。

如果截图、OCR、第三方文件解析或模型调用可能包含敏感原文，也必须纳入数据流审阅，不能只保护数据库字段。

### 11.4 存储、删除与导出

- 个人版本继续使用 SQLite 保存非秘密的任务、台账、索引和权限元数据。
- 附件、敏感档案、浏览器配置和证据采用独立私有目录；需要保留的敏感内容加密保存。
- 主密钥使用系统钥匙串或等价凭证设施保存，不写入数据库、仓库或日志。
- 浏览器目录包含 Cookie、缓存等独立数据，不能因为档案字段加密就宣称整个 Chrome 配置已加密。第一版对专用浏览器目录使用私有权限和操作系统磁盘保护；强隐私模式使用临时配置并清理。保留登录配置应单独选择，备份/导出另做加密。
- 数据库加密字段按用途和版本管理；密钥丢失要明确告知无法恢复。
- 删除覆盖原文件、解析副本、结构化事实、搜索索引、截图、生成测试残留及缓存。
- 备份按独立期限清理，向用户解释备份中删除生效时间；不承诺未实现的即时全量清除。
- 授权撤销停止后续使用；已发给网站或模型的数据不能靠本地删除收回。
- 导出提供脱敏摘要和用户明确选择的加密完整导出。

当前已有审计和会话记录可能含原始参数，统一脱敏与历史数据迁移属于建设项，不能将现有 SQLite 直接当作已完成的加密资料库。

## 12. 团队协作

### 12.1 团队方案

默认单 Agent。只有可并行、职责明确且预期收益合理时，提出团队方案，说明：

- 成员、职责、输入和返回结果；
- 需要读取的资料、连接器和权限；
- 与单 Agent 相比的收益、费用、耗时及协调成本；
- 失败时如何保留部分结果；
- 最大人数、深度、任务数、时间和费用预算。

用户可以批准、调整或拒绝。拒绝后继续单 Agent 路径，不阻断整个任务。

### 12.2 建议分工

招聘示例可拆为岗位检索、资料核对和表单执行。岗位检索不需要身份证、验证码或完整简历；资料核对返回事实与差异；表单执行者独占当前浏览器写入。

副 Agent 可以提出进一步委派建议，但只能在用户已允许的团队范围内执行。超出成员、权限或预算上限时重新审阅，不无限递归创建团队。

### 12.3 协调与隔离

- 一个浏览器会话同一时刻只有一个执行者。
- 副 Agent 返回结构化结果与证据引用，不直接改写最终业务状态。
- 最终提交由指定执行者和平台审批完成。
- 成员不共享原始凭证；按任务分配最少资料引用。
- 日志保留父子任务关系和实际能力版本。
- 单个成员失败时可重派只读工作，但不得重派未知结果的提交动作。

第一版建议最多 3 个并发成员、委派深度不超过 2 层。该数值是待配置和验证的初始上限，不是 Agent 能力的永久限制。

## 13. 主 Agent 创建 MCP 与能力治理

### 13.1 能力发现

创建 Agent 前，先查询能力目录和已启用版本，再检查 Skill。优先选择经过验证的连接器和适配器，避免每个任务重新生成等价代码。

能力目录记录输入/输出 Schema、资源范围、操作语义、数据流、超时、版本、维护来源和验证报告。

### 13.2 缺能力时的生成流程

1. 记录当前缺口及失败依据，确定是计算规则、控件适配还是外部连接器。
2. 生成扩展提案、代码、接口契约、所需权限、合成样例和验证器。
3. 先做静态检查与隔离测试，不注入用户真实凭证。
4. 需要外部网络/文件/凭证时，通过受控连接器代理请求，不默认开放宿主环境。
5. 展示实际测试结果、未覆盖范围、依赖及维护成本。
6. 用户批准新权限或安全敏感访问后启用，记录不可变版本和哈希。
7. 业务 Agent 固定绑定版本，任务运行中不静默升级。
8. 失败或回归时停用新版本，回到兼容的旧版本或保持受阻。

未知来源代码/依赖的运行和新安全敏感访问需要明确审阅。网页或生成代码自身不能成为授权依据。

### 13.3 发布清单示例

~~~yaml
package: date-range-widget
version: 1.0.0
kind: widget_adapter
operations:
  - inspect_date_range
  - prepare_date_range
required_capabilities:
  - browser
data_access:
  - approved_profile_dates
secret_access: none
arbitrary_host_filesystem: false
arbitrary_network: false
validation_report: report_reference
content_hash: sha256_reference
~~~

该示例为建议清单，不代表当前纯数据能力包已经支持浏览器扩展。现有计算隔离不应为本方案直接放开网络和宿主文件。

## 14. 台账、日志、跟踪与通知

### 14.1 台账

台账按业务对象汇总，显示目标链接、账号别名、资料版本、创建/提交时间、当前状态、回执和最近检查时间。失败和结果未知也入账，但不能标成提交成功。

用户可按公司/对象、时间、状态和 Agent 筛选，查看执行过程及相关证据。更正状态保留来源与修订记录。

### 14.2 三类日志

| 类型 | 主要内容 | 示例 |
|---|---|---|
| 业务台账 | 对象的当前业务状态 | 岗位申请已提交、回执编号 |
| 执行事件 | 谁、何时、用哪个版本执行哪一步 | 文件 v1 上传完成，结果待核对 |
| 诊断日志 | 错误类别、耗时、组件版本 | 下拉框未加载、连接超时 |

统一关联 run_id、step_id、attempt_id、object_id 和 trace_id。日志保存结构化错误码和脱敏摘要，不记录验证码、token、完整身份证、带凭证 URL 或不受控的工具原始输出。

不保存用户完整隐藏推理；可保存简短行动理由与可核对依据。

### 14.3 跟踪

用户审阅后启用，配置对象锚点、来源、频率、有效期、停止条件和通知方式。建议普通招聘状态默认每日检查，具体间隔由站点和用户选择，不作为固定承诺。

- 只读查看目标对象，不重新填写、上传或点击提交。
- 登录过期时暂停对应检查并请求恢复认证。
- “未找到记录”“页面打不开”和“被拒绝”分别处理。
- 状态变化、明确失败或需要用户操作时通知；无变化时保持安静。
- 到达终态、截止时间或预算后停止。
- 本机离线期间显示未检查；恢复后按计划补查，不伪造连续监控。

## 15. 前端页面与交互

### 15.1 页面组成

| 页面/区域 | 关键内容 |
|---|---|
| 创建任务 | 目标、网站/对象、资料版本、数量/时间限制、完成条件 |
| 能力方案 | 复用工具、缺口、Skill、权限和验证情况 |
| 资料档案 | 原文来源、结构化事实、敏感等级、更正和版本 |
| 隐私设置 | 本地保存、模型使用、站点发送、期限和删除 |
| 邮箱与连接 | 真实授权范围、任务过滤、凭证状态、撤销 |
| 团队审阅 | 成员、角色、收益、成本、权限和预算 |
| 任务工作台 | 当前阶段、已完成步骤、下一步、暂停/取消/恢复 |
| 页面与填写预览 | 真实画面、采集时间、字段对照、错误和文件 |
| 最终审阅 | 实际对象、账号、字段、附件和独立提交确认 |
| 台账与跟踪 | 业务状态、回执、检查计划、变化与未读提示 |
| 日志与诊断 | 时间线、错误类别、证据和脱敏导出 |

### 15.2 关键交互规则

- 任务执行状态与聊天回复状态分开显示。
- 按钮点击后立即反馈处理中；结果来自服务端持久状态。
- 失败、取消、过期及未知结果不继续显示可重复执行的旧按钮。
- 弹框标题和底部操作固定，正文可滚动，支持关闭与焦点恢复。
- 关闭弹框不等于取消已经发出的请求。
- 预览失败不阻断正常聊天；旧画面标记时间和失效原因。
- 预览只在用户明确请求时截图，定时只读状态与缓存，避免干扰网站。
- 人工接手期间不后台读写同一页面。
- 仅询问确实缺少的信息，已能通过页面/文件读取的信息不要求用户复述。
- 用户更正字段后，明确区分只改本次任务还是同时更新档案。

### 16.1 实现建议

- SQLite 使用事务、版本号及条件更新处理个人版本的状态变更。
- 第一版采用持久任务表和单个受控 worker，避免立即引入复杂分布式基础设施。
- 状态提交与事件投递采用事务化 outbox 或等价机制，减少“动作完成但前端永远不知道”。
- 截图/附件不直接嵌入每条任务记录，只保存受控引用和元数据。
- 不持久化模式采用临时资源和受限内存状态，明确退出后的恢复限制。
- 浏览器进程/窗口是易失执行资源，不把其存活视为数据库记录存活。
- 未来多用户阶段再评估 PostgreSQL、独立 worker 和队列；新增 owner_id 字段本身不等于完成隔离。

## 17. 接口与工具契约

### 17.1 约束

- 所有接口按用户/工作区、任务及资源归属检查。
- 模型只见获批工具与资料引用，不接受任意宿主路径和代码入口。
- 状态变更使用 revision/条件更新；重复请求使用幂等请求标识。
- 返回真实执行状态与结构化错误，不由前端猜测成功。
- 创建任务或生成计划不等于授权执行。
- 当前本机个人工作区上线公网前，必须先完成认证、授权和执行/网络隔离。

### 17.2 建议新增 HTTP API

以下路径为设计草案，尚未实现。现有 conversations、pending-actions、files、browser、tracking API 保持兼容。

| 接口 | 用途 |
|---|---|
| POST /api/task-runs | 创建任务，绑定目标、资料版本和隐私策略 |
| GET /api/task-runs/{id} | 获取当前状态、阶段、修订与所需操作 |
| GET /api/task-runs/{id}/events | 按游标读取脱敏事件时间线 |
| POST /api/task-runs/{id}/controls | 暂停、继续、取消后续执行或请求核对 |
| POST /api/task-runs/{id}/grants | 保存用户明确授予的任务范围 |
| GET /api/task-runs/{id}/review | 获取当前真实填写对照和提交摘要 |
| POST /api/task-runs/{id}/reconcile | 核对未知结果，不直接重发原提交 |
| POST /api/profiles | 创建资料档案草稿 |
| POST /api/profiles/{id}/versions | 保存用户审阅后的资料版本 |
| POST /api/connector-accounts | 发起连接授权，秘密通过专用流程交换 |
| POST /api/connector-accounts/{id}/revoke | 撤销后续访问 |
| POST /api/team-plans/{id}/decision | 批准或拒绝明确团队方案 |
| POST /api/capability-versions/{id}/activation | 审阅验证结果与权限后启用扩展 |
| POST /api/privacy/exports | 创建用户选择范围的导出任务 |
| POST /api/privacy/deletion-requests | 展示删除范围后执行数据清理 |

### 17.3 模型侧工具分组

- 资料：列出版本、读取获批事实、报告缺失、引用保护字段。
- 浏览器：读取/查找/检查、准备操作、读取验证结果。
- 邮箱：查看授权连接、等待匹配的认证结果，不提供任意邮件写入。
- 任务：读取计划与当前步骤、报告证据、提出恢复方案。
- 跟踪：查询台账、提出只读跟踪方案、读取检查结果。
- 协作：提出团队/委派方案、读取成员结果。
- 扩展：发现已有能力、提出缺口和测试方案。

最终提交、任务授权、凭证授权和包启用由平台接收真实用户决策；不能仅靠模型调用一个“approve=true”工具完成。

### 17.4 错误契约

建议统一返回 error_code、user_message、retry_class、side_effect_state、recovery_action 和 evidence_refs。

关键错误类别：

- SNAPSHOT_STALE：重新观察，不复用旧审批。
- RESOURCE_VERSION_CHANGED：重新审阅资料版本。
- AUTH_REQUIRED / AUTH_EXPIRED：认证或恢复连接。
- AMBIGUOUS_TARGET：目标存在歧义，需要进一步读取/选择。
- WIDGET_UNSUPPORTED：记录控件证据和能力缺口。
- RESULT_UNCERTAIN：先核对，禁止直接重投。
- CAPABILITY_REVOKED：停止使用，不能由生成包自行恢复。
- BUDGET_EXCEEDED：暂停并展示费用/调用情况。

当前错误字符串逐步映射到这些结构化类别，迁移期间保留原有兼容字段。

## 18. 实施路线与交付物

阶段以验收完成为边界，不在缺少工作量评估时承诺日期。

### P0：范围与契约收口

交付：

- 确定个人本机版本边界与第一批目标网站类型。
- 统一任务/对象/步骤/审批/证据模型。
- 定义资料来源、日期精度、操作后置条件和错误类别。
- 建立真实已知失败案例与合成回归集合。
- 保留现有浏览器和审批成果，不回退到逐资源放行补丁。

出口：可以从目标到回执逐步说明每条状态由谁维护、凭什么推进。

### P1：可靠单 Agent 闭环

交付：

- 通用任务状态、执行意图、互斥与检查点。
- 结构化资料和版本、字段映射与更正。
- 日期区间、级联选项、多段经历等基础适配器。
- 文件上传验证、填后读回、差异预览。
- 最终提交审批、结果未知核对与业务防重。
- 台账联动、脱敏事件与任务面板。

出口：多个表单结构的端到端闭环成立，异常恢复不依赖用户复述整段过程。当前逐批审批继续有效；任务级连续执行另做权限回归。

P1 以合成资料或用户明确授权的普通资料验收；敏感资料的持久使用和邮箱自动认证依赖 P2，不能以明文秘密写入任务表来临时替代凭证设施。

### P2：隐私与认证自动化

隐私数据流约束在 P0/P1 即适用；本阶段交付完整持久凭证设施。

交付：

- 本地加密档案、敏感值引用、密钥管理与删除/导出。
- 模型使用和网站发送的独立授权。
- 邮箱连接器、请求绑定的验证码使用、授权撤销。
- 本人验证接手与自动续接。
- 保存策略与临时资源清理验证。

出口：秘密不会进入模型和普通日志，错误验证码/账号/发件来源不会导致错用认证。

### P3：长期运行与跟踪

交付：

- 持久 worker 恢复、过期租约回收和未知结果核对。
- 只读状态检查、登录失效暂停、变化通知与停止条件。
- 离线/重启、限流、费用和任务取消处理。

出口：重启后不会自动重投；跟踪未运行或无法读取时如实显示。

### P4：扩展生成与团队

交付：

- 能力目录、连接器缺口报告及独立 MCP 扩展提案。
- 合成测试、权限审阅、版本固定与回退。
- 团队方案、用户决策、有限委派、预算与角色隔离。
- 跨成员证据传递与单浏览器写入互斥。

出口：同一底座创建至少一种非招聘任务，证明复用来自通用运行与工具，而不只是招聘 Prompt。

## 19. 验收计划与度量

### 19.1 验收层级

1. 单元测试：解析、分页、状态、权限、版本、精度、脱敏与幂等。
2. 真实浏览器合成测试：本机表单、实际文件选择和服务端收件核对。
3. 外部真实页面试点：用户明确授权的数据、站点和操作，最终提交单独确认。
4. 跨任务验证：以非招聘流程复用运行器、资料映射和记录。

不将合成成功率写成全部网站兼容率。报告区分模型规划、工具执行和业务完成。

### 19.2 必测矩阵

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A01 | 大页面与末尾目标 | 可通过分页/查询取得完整可访问内容，前页引用不因分页失效 |
| A02 | iframe 无自身文字的上传容器 | 返回真实引用、审批后实际收到正确文件版本 |
| A03 | 日期/年月与日期区间 | 精度正确、起止正确、缺日不编造、“至今”可核对 |
| A04 | 自定义下拉/级联地区 | 选项真实、逐级一致，错误可见 |
| A05 | 多段经历 | 行与记录不串位、字段读回一致 |
| A06 | 自动解析简历 | 区分文件选中、上传成功、解析完成，逐项校验解析值 |
| A07 | 用户改值/文件更新 | 原计划停止或重新核对，不覆盖未授权修改 |
| A08 | 焦点/样式变化 | 不误判为业务内容变化 |
| A09 | 邮箱验证码 | 只匹配当前请求，错误来源/过期/已用码拒绝，不记录原值 |
| A10 | 本人接手 | 接手时无后台读写，交回后不重放已完成操作 |
| A11 | 双击与双窗口 | 本地只认领一次；UI 与持久状态同步 |
| A12 | 提交后超时 | 进入待核对，先查回执，不自动再次提交 |
| A13 | 重启与浏览器关闭 | 从检查点核对现场，旧引用/审批不恢复 |
| A14 | 隐私设置 | 临时模式退出后不可恢复；保留模式按选择保存和清理 |
| A15 | 恶意页面/邮件指令 | 无法扩大权限、读取无关资料或改变资料发送目标 |
| A16 | 团队 | 超范围委派被拒绝，同一浏览器只有一个执行者 |
| A17 | 跟踪 | 无变化不通知、登录失效暂停、终态停止 |
| A18 | 非招聘任务 | 不改底层执行器即可配置并完成另一类明确任务 |

已完成的大表单合成基线为 141,421 字符、901 个元素和 iframe 末尾上传入口；该历史结果可作为回归起点，不能替代新增功能验收。

### 19.3 报告指标

- 无额外手动补操作的任务完成比例，按站点/控件类型分别报告；
- 字段映射正确率、读回一致率及缺失信息识别情况；
- 文件发送正确率、解析核对结果；
- 每个成功任务的用户操作次数、耗时与模型费用；
- 结果未知次数、重复提交次数、恢复成功情况；
- 敏感值进入模型/日志的泄露检查结果；
- 团队相对于单 Agent 的耗时和费用变化。

未知结果、用户取消和网站不支持分别统计，不将它们从样本中隐去。

## 20. 主要取舍与待决策项

| 取舍 | 当前建议 | 重新评估时机 |
|---|---|---|
| 本机与服务器 | 先本机个人版；长期无人值守需独立执行环境 | 用户需要关机后仍运行 |
| 通用控件与站点适配 | 通用优先，失败证据驱动适配器 | 多站出现相同结构失败 |
| 每批审批与任务授权 | 保留现有逐批模式，逐步增加有界任务授权 | 权限与敏感数据代理完成验收 |
| 单 Agent 与团队 | 默认单 Agent，明确收益时提案 | 只读可并行任务成为耗时瓶颈 |
| 保存与隐私 | 用户按类别选择，临时模式说明恢复限制 | 需要跨会话复用或长期跟踪 |
| 多用户基础设施 | 暂不凭当前本机服务公开上线 | 准备真实多用户试点前 |
| 邮箱提供商 | 先支持一种用户实际使用的正式授权方式 | 确定首批邮箱及部署形态 |
| 模型数据处理 | 所选模型数据流明确告知；拒绝时走本地/本人路径 | 接入不同模型或外部解析服务 |

进入实施前应明确：首批试点网站类型、邮箱提供商、本机/服务器形态、任务上限、保存默认值和团队初始预算。这些是配置及范围选择，不阻止先实现通用任务模型和合成验证。

### 22.2 补充要求

1. **基础设施由平台维护，主 Agent 只组合。** 浏览器、邮箱、文件、敏感资料库、台账与日志不由每个 Agent 生成；只有站点适配和纯数据处理缺口才生成独立 MCP 扩展。
2. **敏感值不进模型。** 当前模型为云端服务，身份证等只以 `protected` 引用出现，由本地代理在执行时填写；审批与日志只显示掩码。
3. **缺失信息问卷与开放题。** 资料中没有的字段生成问卷，不编造；开放题由 Agent 起草，用户审阅后填写。日期按精度保存，月精度不补日。
4. **站点账号注册**属于敏感操作，需要用户确认，密码进入本地凭证库。
5. **批量限速与条款提示。** 每日/每站上限默认开启，提示网站条款与账号风险。
6. **邮箱也作为证据和跟踪来源。** 投递确认邮件、面试邀请可作为回执与状态依据（同一 Gmail 只读连接）。
7. **隐私选项的冲突需要说明。** 关闭台账：不创建台账对象、不能长期跟踪，但任务表仍保留最小业务标识用于防重；关闭日志：任务结束后只保留状态变更事件。
8. **前端补充页面**：权限与数据去向审阅、任务时间线与接手按钮、字段对照（来源行与网页读回值）、缺失信息问卷、隐私中心。
9. **泛化验收**：除招聘申请模板外，提供“只读巡检”模板，同一运行器无需修改即可执行。

### 22.3 P0 实施记录

已实现（后端，见 [task_service.py](../backend/app/services/task_service.py)、[tasks.py](../backend/app/models/tasks.py)）：

- `task_runs / task_steps / step_attempts / task_events` 表；任务关联既有会话与台账对象（work items）。
- Run 状态机（第 9.2 节全部状态）＋ phase；非法转换返回 `INVALID_TRANSITION`；用户控制带 revision。
- 模板：`application`（申请办理）与 `inspection`（只读巡检）；模板决定对象标识字段与允许的步骤类型。
- 步骤外部影响等级（none / sends_data / commit），计划只能提高不能降低；提交步骤必须声明可核对完成条件并强制审批。
- 执行尝试：先持久化意图，再 `mark_dispatched`，最后按实际读回值判定；有外部影响却无法观察结果 → `uncertain` → Run 进入 `reconciling`，需提供证据核对，核对后进入 `paused` 由用户继续。
- 防重：同一 Agent 下同一业务标识只能有一个进行中任务；提交成功或结果未知的对象永久阻止再次提交。简历版本不参与标识。
- 审批：提交步骤须引用本会话已批准的 pending action，每个确认只能用于一次执行。
- 重启恢复：已发送的外部操作置为 `uncertain`，未发送或只读的置为 `failed`；任务进入 `reconciling` 或 `paused`，不会自动重放。迟到结果只记事件，不覆盖新状态。
- 预算：步骤数与单步尝试次数上限，超出后任务 `blocked`。
- 结构化错误：`error_code / retry_class / side_effect_state / recovery_action`，保留原 `detail` 字段兼容旧前端。
- 日志脱敏：敏感键名（密码、验证码、授权码、身份证、token、cookie 等）整体隐藏；身份证号、银行卡号、手机号、邮箱、URL 凭证参数按模式遮盖。
- 资料模型：带精度的日期与区间、固定版本的字段来源、`protected` 引用禁止附带原文。

HTTP 接口：`GET /api/task-templates`、`POST/GET /api/task-runs`、`GET /api/task-runs/{id}`、`GET .../events`、`POST .../controls`、`PUT .../plan`、`POST .../steps/{step_id}/resolution`。执行尝试的开始/结束只供平台运行器内部调用，不接受浏览器端上报结果。

P0 尚未包含：任务页面前端、运行器 worker 与现有浏览器/审批工具的接线、模型侧任务工具、资源租约。它们属于 P1。

### 22.4 P1 实施记录（单 Agent 闭环，合成网站验收）

已实现：

- **资料档案**（[profile_store.py](../backend/app/storage/profile_store.py)）：基础信息、教育/经历（带精度的日期区间与“至今”）、技能、常用回答；每次保存生成不可变版本；Agent 草稿须用户保存为正式版本后才能被任务使用；检测到身份证号/银行卡号时拒绝保存，提示改用敏感资料库（P2）。任务创建时固定一份资料版本。
- **按路径取值**：`basics.name`、`education.0.period.start` 等由平台从固定版本取值；`date:month[:分隔符]` 只能降低精度，不补日；结束为“至今”时要求改用页面的“至今”选项；下拉选项不同时用 `option:<值>` 转换并在审阅中标注。
- **模型侧任务工具**（新能力 `tasks`）：`task_current / task_plan / task_ask_user / task_check_step / task_prepare_fill / task_prepare_commit / task_complete`。模型只决定“填到哪里、来源是什么”，值由平台取出；起草内容（inferred）单独标注。
- **审批接入任务**：带 `task_step_id` 的确认在执行前开始尝试并标记已发送，执行后用**逐控件读回值**（两个浏览器方案均已支持，含勾选状态、所选文件名、下拉标签）判定；执行中断（502）判为结果未知，执行前校验失败判为未发送；取消确认使任务回到执行中。
- **最终提交审阅**：汇总前序填写/上传步骤每个字段的来源、页面读回值和核对结果；提交以回执正则判定，回执写入台账对象。
- **缺失信息问卷**：`waiting_user` 时任务页显示问题，回答后继续；回答值不写入日志。
- **前端**：任务页（新建任务：目标链接自动推导网站与岗位编号、资料版本、是否副 Agent 协助及利弊、四项隐私选项；任务详情：控制按钮、问卷、步骤、字段对照、结果未知核对、脱敏日志）、资料档案编辑、审批弹框中的填写来源表与最终提交审阅表。
- 修复既有问题：消息输入区隐藏的上传控件被 `.composer input` 撑满 100% 宽度，导致页面横向滚动。

验收（[test_task_e2e.py](../backend/tests/test_task_e2e.py)，真实无头 Chromium＋本机合成申请站点）：读取 → 资料缺少期望薪资时询问 → 取消一次填写（未发送）→ 填写 8 个字段（含下拉、年月、起草内容）并逐项读回一致 → 上传附件读回文件名 → 提交前合成站点收到 0 次提交 → 最终审阅 9 个字段全部核对 → 确认后收到恰好 1 次提交、值与文件内容一致 → 回执 SYN-0001 写入台账 → 同一岗位再次创建任务被拒绝。另一用例：站点把输入改为大写，读回不一致判为未通过，修正后重填通过。

尚未包含 / 已知限制：

- 资源租约（同一浏览器跨任务互斥）仍依赖“同一任务单一执行中尝试”和既有审批条件更新，独立租约表留到 P3。
- 敏感资料库、Gmail 验证码（P2），长期运行 worker（P3），团队与扩展生成（P4）尚未开始；“允许提出团队方案”目前只保存选择。

### 22.5 自动化改进阶段 A（表单引擎）

真实站点试用暴露的问题：一次投递弹出 48 次确认（45 次只含 1 个操作）、40 次点击（17 次为无名称的自定义下拉）、106 次整页读取，Agent 绕过任务流程直接驱动浏览器。用户决定：任务默认“只在最终提交前确认”；任务进行中禁止普通浏览器写入；先做阶段 A。

已实现（[form_engine.py](../backend/app/platform/form_engine.py)）：

- **整表结构提取**：一次返回每个字段的 key、标签、分组、控件类型（text/textarea/select/custom_select/cascader/date/radio/checkbox/file）、必填、当前值、选项；自定义下拉与级联首层由平台展开读取后关闭。字段以平台写入的 `data-wb-*` 属性定位，执行时按“分组|标签|类型|序号”重新匹配，不依赖快照元素编号。
- **控件适配器**：文本（失败时原生赋值重试）、标准/自定义下拉（按选项原文、唯一包含匹配兜底）、省/市级联逐级选择、日期（只输入不回车）、单选/勾选、上传（内置浏览器用内存文件，本机 Chrome 经官方 MCP 选择器上传）；每个字段前后自动关闭残留浮层（Esc，必要时点击页面空白）。
- **安全约束**：从不按回车（在表单内会触发提交——验收中实际发现并修复）；填写中页面地址变化立即停止并报告；已正确的字段跳过不重写；选项值必须是页面选项原文。
- **两个浏览器方案共用同一引擎**：官方 MCP 的 click/type/evaluate 支持“唯一选择器”作为目标。
- **任务工具**：`task_read_form`、`task_fill_form`（一次最多 80 个字段，整表一个步骤、一次确认；有授权时直接执行）；字段逐项给出读回结果与判定。
- **默认授权**：新任务默认“自动填写，只在最终提交前确认”；最终提交始终人工确认。
- **任务进行中禁止 `browser_prepare_actions` 写页面**，必须走任务工具。

验收（真实无头 Chromium＋Element 风格合成招聘页）：上传简历 → 站点自动解析回填姓名邮箱（引擎跳过）→ 一次问卷补齐性别/政治面貌/籍贯 → 一次 `task_fill_form` 填完单选、两个自定义下拉、选完不收起且遮挡后续字段的级联、两个年月字段、文本域，全部读回一致 → 填写过程中站点 0 次提交 → 最终审阅 11 个字段全部核对 → 用户确认 1 次 → 回执入账、提交值与文件内容一致。整个过程用户只需回答 1 次问卷、确认 1 次提交。

尚未包含：可重复经历栏（“添加一段”后填第 N 组）、先比对站点解析结果的自动差异建议、总表内直接改值、提交前截图、按站点积累适配规则（阶段 B/C）。本机 Chrome 方案的引擎路径仅单元覆盖，需在真实站点验证。

### 22.6 阶段 B 改为半自动（A+B）：先上传、自动填文本、下拉清单、提交前整表纠错

金证科技（北森 zhiye.com）实测暴露：阶段 A 的识别依赖组件库类名，只认出 46 个文本框，下拉、日期、上传全部漏掉；字段名取成占位符“请输入”；退回逐步点击后按文字找选项会点到其他字段的隐藏列表，核对条件只是“页面地址存在”，所以显示成功但值没存上。用户选择不死磕全自动，改为：

1. **先上传**简历，等网站自己解析回填（网站自己的下拉由网站代码填）。
2. **按行为识别**：字段名优先取相邻元素文字，占位符只兜底；只读输入框、只显示“请选择”的元素视为下拉；表单行外的隐藏上传框也纳入；选项只取点击该字段后新出现的元素，不在整页按文字匹配；上传区名称首次识别后固定。
3. **文本自动填**，网站已回填的也传入，平台跳过一致的、纠正解析错的；下拉/日期只试一次，失败标记为手动，不重试、不逐个点击；整表填完再读一遍，捕捉被页面改掉的值。
4. **提交前整表复核**（task_check_form，task_prepare_commit 自动触发）：与平台填写的资料逐项对比，检查手机号、邮箱、身份证校验位、年龄、日期格式和网站报错；文本不一致自动重填一次；其余列入任务页清单，任务转为等待用户，用户在浏览器里处理后点“重新核对”（只读）。复核通过后失败的填写批次视为已被覆盖；最终审阅展示重新读取的整张表，含“网站已填”的值。
5. 工具审计日志写入前脱敏（证件号、卡号、手机号、邮箱），不截断。已存在的旧记录需另行清理。

验收：仿厂商结构的合成页（无组件库类名、标签在相邻元素、div 下拉加两份都含“山西省”的隐藏列表、行外隐藏上传框、解析器填错手机号和学校、选籍贯会清空地址、日历和需搜索的下拉不可自动操作）完整跑通，填写期间 0 次提交，最终提交内容全部正确。

### 22.7 2026-10-21 决定：砍掉自动投递，改为资料包 + 投递台账

用户决定不再做替用户填写、提交网申的功能。§22.3–22.6 中的任务框架（任务/步骤/尝试/事件、自动填写授权、整表填写、页面点击、最终提交审阅、提交前复核纠错）已从代码中删除，删除前的源码打包在 `backend/data/archive/`（不入库）。保留并改造为：

1. **投递台账**（applications 能力）：岗位、链接、截止日期、阶段（待投递/准备中/已投递/笔试测评/面试/offer/未通过/放弃）、下一个日程、备注；阶段与修改有历史；任务页显示 3 天内截止（未投递）和 7 天内日程的提醒，顶部按钮显示临近数量。
2. **资料包**：Agent 只读读取网申表单（不点击、不展开、不在页面留标记），按用户审阅过的资料版本生成逐项可复制的内容，按页面顺序排列；对话中用户提供的值、Agent 起草的长答案、选项说法转换、需上传的文件分别标注；资料中没有的必填项列为“请自行填写”，不编造。用户可在台账中改写任意条目。
3. 资料档案、日志脱敏保留；浏览器面板通用的“确认后操作网页”功能保留，但 Agent 提示中禁止用于网申表单。
4. 旧的 tasks 能力在启动迁移中自动换成 applications。旧任务数据表仍在本机数据库中（未自动删除）。
