# 带引用的知识库问答

笔记 MCP 的搜索和原文读取也支持引用卡片、原文快照和历史恢复；需使用带 `workbench.notes.v1` 来源协议的新版服务。目录浏览不会被记为读过原文。配置及认证方式见 [本地笔记 MCP 服务](./notes-mcp.md)。

## 原文链接与片段高亮

回答中的引用编号和来源文件名均为可点击链接。点击后打开原文预览，显示引用版本的完整文档、行号，并以黄色高亮实际返回的切片或读取片段；预览会自动定位到片段，也可通过“定位引用片段”按钮返回。预览使用文本方式展示，不执行文档中的 HTML 或脚本。

新版引用记录保存字符起止位置，高亮按原文位置定位，不会把相同词句在全文中的其他出现一并标记。前端按 Unicode 字符处理 Python 偏移，包含 emoji 的文档也可正确定位。旧引用缺少偏移时，仅在其标明的起始行内尝试唯一的原文匹配；原文版本、内容或位置无法核实时，只展示当轮保存的片段。

完整原文按文档版本存入 `knowledge_document_versions`，不会随当前文档更新或删除而变化，以维持历史引用。升级会为当前已有文档建立存档，无法恢复升级前已被替换或删除的完整旧版本；这类历史引用继续显示已有片段。来自其他独立数据库的远程 MCP 资料，如果本工作台没有对应版本，也回退到片段预览。全文仅在用户打开预览时由页面读取，不会因此额外发送给模型。

预览接口：`GET /api/knowledge-bases/{base_id}/documents/{document_id}/versions/{version}`。不存在或不属于该知识库的版本返回 404。

在 Agent 知识库绑定和检索工具之上，增加回答中的引用按钮、资料来源卡片和原文快照。引用来自该轮实际返回的检索片段。

## 页面体验

1. 刷新页面并选择已绑定知识库的 Agent，例如“知识库检索助理”。
2. 新建对话，输入“请检索邀请链接的有效期，给出简短回答并引用知识库原文”。
3. 回答中显示 `[1]` 等引用按钮，下方显示“回答依据”和来源卡片。
4. 点击引用按钮或来源卡片，查看知识库名称、文件名、版本、章节、行号和对应原文。
5. 刷新页面后，重新选择 Agent 和该会话，仍可打开原引用。

来源卡片分为回答已引用的资料和折叠的“其他检索结果”。后者是工具检索到但回答没有引用的片段，不作为已采用的回答依据展示。

## 没有依据时

页面根据真实工具调用区分以下状态：

| 状态 | 展示含义 |
| --- | --- |
| matched | 找到了片段；只有回答中的链接对应实际来源时，才显示“回答引用了 N 处资料” |
| no_match | 工具成功执行但没有匹配，提示当前回答缺少本轮知识库依据 |
| not_searched | 本轮没有执行知识库检索，不把回答标成已有知识库依据 |
| failed | 检索失败，提示无法核验资料依据 |

模型使用不存在、旧轮次或编造的来源编号时，页面显示“未核验”，不会生成可点击的原文。正文中的普通外部链接保持普通链接，代码块和行内代码里的引用示例不计入已引用资料。

系统提示词要求先查资料、按原文回答并使用工具返回的链接；没有匹配时说明未找到，不推测具体制度。模型是否正确理解原文仍需评估，引用链接可核验不等于结论已经通过事实审查。

## 来源快照与历史消息

每轮对话生成独立的来源编号，同一轮重复检索同一版本的片段只登记一次。不同版本的片段分别记录，不混用原文。

工具使用与管理页相同的重叠合并检索。引用按文档、内容版本、原文区间和内容哈希识别；同一个代表片段 ID 在不同查询中合并成不同范围时，使用独立引用编号，避免前一份原文快照被覆盖。检索结果中的 `id` 是最高排名命中的代表 ID，`source_chunk_ids` 记录这一组合并的全部片段。

引用保存的是本轮检索时的片段快照。文档后续更新、删除或解除 Agent 绑定，不会修改历史回答的原文快照；这些操作仍会影响后续的工具查询范围。删除知识库不会自动清除聊天记录中已经保存的资料。

旧消息保留原来的展示，不从相邻轮次的审计记录猜测或补写引用。需要新的来源展示时，请重新提问。

## 接口和存储

- SSE 新增 `knowledge` 事件，包含 `evidence`；它与 `delta` 文本事件分别传递。
- `evidence` 包含 `status`、`queries`、`failed_searches` 和 `citations`。
- 每个来源包含 `citation_id`、知识库 ID 和名称、文档 ID 与版本、片段 ID、文件名、章节、起止行号及原文。
- 模型工具结果增加 `citation_id` 和 `citation_link`，回答使用 `[序号](#source-实际编号)`。前端只将本轮真实来源的链接转换为引用按钮。
- `messages.metadata` 保存回答的来源快照和完成状态，与回答正文在同一次写入中持久化。启动时自动增加旧数据库缺失的字段。
- `GET /api/conversations/{id}/messages` 在新回答上返回可选 `knowledge` 和 `status`，旧消息继续兼容原来的 `role`、`content` 格式。
- 回复失败或用户断开连接后，已收集的原文快照和已收到的文本仍会保存，回答标记为未完成。

知识库查询继续使用现有 BM25 关键词检索，未引入向量服务或新的模型依赖。

## 验证

后端 80 项、前端 24 项测试和前端生产构建通过。新增覆盖实际 SDK 工具返回来源、流式事件和历史恢复、跨轮编号隔离、文档更新与删除后的快照、重复并发检索、空结果、失败、断流及旧数据库迁移。

页面使用现有模型验证邀请链接问题：模型检索后回答有效期为 72 小时，显示可点击引用；原文弹窗显示对应文件 v1、第 1–34 行。刷新并重新选择会话后，引用和来源卡片仍保留。

另用不存在的编号 `QZX987654ABC` 验证空结果：模型明确回答未找到资料，页面展示“已检索，未找到匹配资料”，没有生成引用。页面控制台未记录错误或警告。
