# 执行记录、状态跟踪与文件恢复

面向当前本地个人工作区的通用能力。投递、订单、审批和工单可以使用相同的记录与跟踪模型；本版的外部状态来源为公开网页和独立浏览器，没有招聘网站专用适配或远程 MCP 状态连接器。

## 使用

1. 原有审批操作会自动记录，包括浏览器操作、文件更新和工时演示。侧栏与顶栏「记录与跟踪 → 执行记录」可查看目标、操作、结果和当时的文件版本。浏览器点击完成记为“结果待核实”，不直接判断业务提交成功。
2. 在 Agent「基础能力」启用「记录与跟踪」。需要查询网页时还要启用联网检索或浏览器。构建助手可为新 Agent 选择这些能力；旧 Agent 不会被静默扩大权限。
3. 让 Agent 读取实际页面，再提出跟踪方案；也可从执行记录或当前会话手动新增。填写查询入口、唯一对象标识、检查间隔、状态关键词与结束状态。浏览器方式可选择当前会话已打开且登录完成的页面，并限定唯一 CSS 区域；这是高级配置。
4. 新方案默认暂停，核对配置后点击「启用定期检查」。可立即检查、暂停、结束或调整配置。调整查询目标或规则会清空当前状态并暂停，历史检查记录保留。
5. 状态变化、首次得到状态、检查受阻或恢复时增加站内未读提示；重复相同结果或相同错误不会重复提醒。没有电子邮件、短信或系统推送。
6. 查询只做公开 GET 正文读取或关联浏览器的同站点导航与文字读取，不填写、点击或重新提交原操作。用户正在接手页面时检查会受阻；后台刷新将使旧操作快照失效，交回后需重新读取再规划。

检查要求唯一对象标识只出现一次，并且附近文字只命中一个状态规则；否则保留原业务状态并记录原因。规则是确定性的关键词识别，不是通用页面语义理解；它不能证明所有网站的业务含义都已正确识别。需要将范围限定到正确对象，重叠、否定或含糊关键词会造成歧义，必须人工核对。单次检查读取的前 20000 字符外的对象不会被推断为不存在。

## 文件更新与重新关联

聊天附件仍可通过上传使用。开始一个会话后，顶栏「文件与版本」可更新附件或明确关联后端电脑上的单个本机文件，不扫描目录；模型工具不能指定宿主路径。

- 本机关联：用户填写完整路径并授权读取，保存解析文字和原始字节的 v1 副本。
- 检查：区分内容变化、文件找不到、权限不足与其他连接问题。正文读取和浏览器上传前都会检查，失效时提示用户是否移动、重命名或修改了文件。
- 更新：关联内容变更后，用户可点击读取并保存新版本；模型的 `update_file` 只提出更新计划，需网页确认后执行。也可上传替换文件，或填写新路径重新关联。
- 版本：文件 ID 保持不变，历史文件名、字节、正文、内容指纹和时间保留在版本表。上传替换会转为上传副本，解除原本机路径关联。
- 审批：浏览器上传清单包含具体版本和指纹。确认前预先检查所有依赖文件，任何版本变化都会在首个填写操作之前拦截；不得默默改用最新文件。缺少版本的旧清单需重新生成。
- 历史：原执行参数保留当时使用的版本，改名或更新后仍可查看原版本。撤销能力不清除模型已有的会话历史。

支持 PDF、DOCX、TXT、MD、CSV、JSON，单文件 2 MB；同会话最多 50 个文件，原始文件及其版本总计最多 20 MB。本机关联检查按读取/使用触发，没有磁盘目录监控；更换路径需要用户明确操作。文件字节不变的时间戳变化不会生成新版本。

## 持久化与后台调度

沿用 SQLite：

| 表 | 内容 |
| --- | --- |
| `work_items` / `work_item_events` / `work_item_actions` | 待办计划、受阻原因、修订历史与审批关联 |
| `work_item_attempts` | 独立保存页面读取尝试、响应码、结果和错误，不代表执行业务操作 |
| `execution_records` | 审批动作的一对一执行记录、目标、状态与结果 |
| `tracking_tasks` | 查询配置、关联对象、当前业务状态、修订号、下次检查时间、租约和未读计数 |
| `tracking_checks` | 每次检查前后状态、正文依据、URL、错误和时间 |
| `conversation_files` | 当前文件版本和用户明确关联的本机路径 |
| `conversation_file_versions` | 不可变版本的原始字节、解析文字、文件名及内容指纹 |

现有文件字节存于数据库，继续随版本归档，数据库备份即可保留这些资料；无需引入对象存储。浏览器登录态依旧只在内存中，重启后需要重新打开并关联页面。大规模资料和多人部署时再评估 PostgreSQL 与独立文件存储。

```mermaid
flowchart LR
    A[生成确认清单] --> R[事务内保存执行记录]
    R --> U[用户确认或取消]
    U --> E[执行并保存结果]
    E --> V[浏览器结果待核实]
    V --> P[提出跟踪方案：默认暂停]
    P --> H[用户审阅启用]
    H --> Q[后台领取到期任务]
    Q --> O[只读观察与唯一状态匹配]
    O --> S[保存状态、依据及下次时间]
    S --> N[有变化或受阻时站内提示]
```

服务启动后每 5 秒领取一个到期任务，检查间隔最少 5 分钟。任务与到期时间持久化，服务停机时不检查，重启后继续处理到期任务。SQLite 事务领取 90 秒租约，完成时核对租约令牌和配置修订号，防止重叠检查或旧结果覆盖暂停/编辑。故障情况下允许重复只读观察，不承诺严格一次执行；不会重跑原业务操作。没有持久化浏览器凭据或无人值守重新登录。

检查失败保留上次业务状态。权限撤销、浏览器会话丢失、唯一对象缺失或状态区域失效会阻塞任务，用户处理后恢复；临时网络错误保留活动状态，按配置间隔重试。执行中断的审批不能重新确认；执行记录中超过十分钟仍处于执行中的项显示待核实。操作去重基于审批 ID，不是全平台业务对象唯一约束：对同一岗位的不同操作仍需 Agent 查询记录和用户核对。

当前数据在本地工作区共享，尚无多用户所有权与账号隔离。关闭网页不影响后台检查；电脑或后端停机期间暂停。源代码推送不备份数据库、本机文件或浏览器登录态。

## 验证

- 自动化覆盖默认暂停、启用与结束、状态歧义、失败保留原状态、通知去重、撤权、租约与过期结果、并发领取、重启调度、会话隔离、文件版本、改名重关联、权限故障、更新审批与上传前校验。
- 真实 Chromium 的合成申请确认前提交数 0，确认后为 1，重复确认仍为 1。跟踪启用后后台自动取得“处理中”，随后人工触发立即检查取得“已结束”并停止；原操作记录由待核实转为已核实。
- 合成本机文件修改后提示确认更新至 v2，改名后提示找不到，用户重新关联至 v3，仍能在页面读取 v1 原文。合成数据使用独立数据库，未向企业投递。

## 工作事项：办理前与受阻时也能记账

「记录与跟踪」新增「工作事项」。用户或模型可保存待处理、受阻、取消三种计划状态，记录稳定标识、名称、目标页面、实际原因与下一步。保存后返回 `work_` ID；聊天中的清单没有该 ID，就不代表已经持久化。模型只应保存用户已选定要办理的对象，不自动把所有推荐变成待办。

同一会话中的稳定标识唯一；完全相同的创建请求复用原记录，内容不同则必须先读取 ID 与版本后更新。更新采用修订号校验，保留历史。运行时工具按 Agent 隔离，修改与关联审批限定原会话。事项不能由模型标记“已提交”或“已完成”。

浏览器操作可传 `work_item_id` 关联目标网址完全相同的事项，审批创建和关联在同一事务保存。已有执行的事项不能换目标；取消的事项禁止再生成或执行关联操作。计划状态与实际执行状态分别显示，取消计划不撤销已发生的操作。用户可从事项历史打开执行回执与后续跟踪依据。

新增表：`work_items` 保存当前计划，`work_item_events` 保存修订历史，`work_item_actions` 关联审批。它们与既有执行记录、状态跟踪、文件版本共同保存在 SQLite。不是自动重试队列，也不代表已具备所有招聘网站适配能力。

公开网页请求的请求头按大小写不敏感合并，避免默认 User-Agent 与 Chromium 的 user-agent 同时发出导致 IIS 返回 400 Invalid Header。真实公开入口对照验证：修复前小写浏览器头返回 400，修复后三种请求头写法均返回 200。网页 HTTP 200 不代表岗位有效或业务已成功。

首次真实受控浏览器验收时，金证科技详情链接仍超时，已保留受阻事项。后续排查和恢复结果见下节。


## 浏览器动态页面恢复与读取尝试

响应转发曾把 CDN 的重复 `Vary` 字段用换行拼接，造成 Chromium 收到主文档 200 后，解析阻塞在脚本上。对照验证只改 `Vary` 合并方式即可继续加载岗位接口；正式修复将响应头名称转为小写、普通重复字段按逗号合并，仅 `Set-Cookie` 使用 Playwright 支持的分行表示。Cookie 有逗号日期时也不会被拆坏，原有站点、请求方法、资料传输和审批限制保持有效。

DOMContentLoaded 后初始正文和元素都为空时，最多等待 5 秒出现可见内容后重新取快照。已有 HTTP 响应但内容仍未就绪时，返回警告并保留会话，供 `browser_read` 或用户接手；没有响应和可用内容的失败仍关闭会话。HTTP 200、首屏导航可见和业务提交成功分别处理，不能互相推断。

对启用「记录与跟踪」的 Agent，`browser_open` 开始前查找当前会话中目标网址完全相同、唯一且未取消的工作事项。匹配时先记录读取中，再保存失败、空内容、部分内容、可读取或 HTTP 错误。共用同一入口的多个事项不自动猜关联，其他会话、其他网址和已取消事项不关联。计划修订号与状态不受读取尝试自动覆盖；打开成功不表示已经填表或投递。界面显示最近读取并可查看最近 20 次尝试。

下一轮对话会获得当前会话最多六条事项摘要及最新尝试，字段明确作为资料而非指令；完整历史继续通过 `read_work_item` 获取。这样，即使模型没有补调用保存工具，实际匹配的重试仍已持久化。

验证：后端 226 项完整宿主回归、前端 52 项与生产构建通过；本机合成页面提供重复 Vary 的脚本复现；真实工作台成功展示给定金证科技岗位页「【2027届校招】大模型应用开发工程师」和职责。没有提交真实个人资料，没有验证账号登录或实际投递。
