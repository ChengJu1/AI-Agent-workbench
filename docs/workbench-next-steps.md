# AI Agent Workbench 下一步计划

更新日期：2026-10-19

本文是建议实施顺序，所列能力尚未全部实现。当前完成情况见 [工作进度](./workbench-progress.md)。

2026-10-19 更新：自定义 Skill 管理与 Agent 绑定已实现，详见 [自定义 Skill](./custom-skills.md)。用户提出的新方向是“上传项目文档 → 拆解任务与验收条件 → 项目巡检 → 自动更新只读 Checklist”，当前只完成 Skill 基础能力，项目接入、任务模型与巡检规则仍待进一步确定。下面保留原有检索优化路线，作为后续可选方向；不代表项目巡检已经实现或已开始执行。

2026-10-19 平台方向更新：已实现平台统一构建助手，支持自然语言生成纯数据处理方法、独立测试、独立 MCP 能力包和 Agent 版本固定与切换，详见 [构建助手](./agent-builder.md)。下一步应根据真实使用反馈选择扩展连接器、能力包管理或任务委派；外部系统方法生成、多用户隔离和自动主副 Agent 协作尚未实现。以下检索优化路线作为可选积累，不再代表当前优先主线。

## 1. 推进方向

先保存当前成果，再提高真实资料的检索和回答质量，随后补齐日常使用能力，最后引入主副 Agent 协作。

检索方向的可选功能是 **BM25＋向量混合检索**。现有“显卡”无法查到 GPU 制度的失败案例可以直接用于验证语义召回收益，已有文档、引用和评估链路也可以继续复用。

## 2. 第一阶段：收口并保存当前版本

### 工作内容

- 整理未提交的知识库、引用、评估、切分及去重计时代码。
- 检查依赖、启动说明、数据库升级及 Docker 配置的一致性。
- 运行后端测试、前端测试与生产构建，处理发现的问题。
- 分批提交并同步私有仓库，记录可恢复的版本。
- 制定数据库和运行数据的备份、恢复步骤；不将密钥和带凭据的数据库直接提交到 Git。

### 验收标准

- 仓库中可以找到当前已完成的功能代码与文档。
- 使用独立环境能按说明启动，并完成创建 Agent、上传资料、检索、问答和查看引用。
- 回归结果与未解决事项有明确记录。
- 完成一次数据库备份与恢复验证。

## 3. 第二阶段：增加混合检索

### 工作内容

1. 选择中文效果、成本和部署条件合适的 Embedding 模型，确定配置方式。
2. 为现有文档片段生成向量，保存模型标识与索引版本。
3. 支持文档新增、更新和删除时同步维护向量索引，并提供全量重建入口。
4. 保留 BM25，新增向量召回通道，将两路候选融合排序，例如采用 RRF。
5. 对融合结果执行原文区间去重，复用现有引用和来源快照。
6. 在检索测试及评估报告中记录检索方式、参数和各阶段耗时。
7. 保留关键词检索模式用于对照，并明确向量服务不可用时的降级状态。

向量存储方案在实施时结合实际数据量选择，第一版避免为小规模资料引入过多基础设施。跨知识库查询仍需遵守 Agent 绑定范围。

### 验收标准

- 在同一文档版本和题集上，可以比较 BM25 与混合检索的结果。
- “显卡→GPU”等预先定义的同义词案例能够召回目标原文。
- 关键词和编号精确查询没有明显退步；退步案例有逐题记录。
- 文档更新、删除后不返回过期向量对应的内容。
- 引用版本、行号和原文位置继续准确，历史引用不受重建影响。
- 对新增依赖、索引成本和检索耗时给出实测结果；效果以评估为准。

## 4. 第三阶段：建立真实资料的质量评估

### 工作内容

- 从现有 Notes 中整理约 30–50 道真实问题及目标原文。
- 覆盖精确关键词、自然语言问句、同义表达、编号、跨段信息和资料不存在等情况。
- 保留当前 18 道演示题，补充新的题集，不删除已有失败题以提高分数。
- 先评估检索，再单独评估模型回答与引用是否支持结论。
- 对无资料问题，检查系统是否明确说明缺少依据，避免仅以空结果测试代替回答质量验证。
- 保存各版本报告，记录文档版本、索引配置和模型配置，便于复现。

### 验收标准

- 新题集可以导入现有评估页面并导出结果。
- BM25 与混合检索有可比较的基线和失败案例分析。
- 回答评估与检索命中率分开报告。
- 对代表性真实问题完成页面验收，能打开支持回答的原文引用。

## 5. 第四阶段：补齐日常使用能力

### 工作内容

- 支持自定义 Agent 的编辑、删除，并明确已有会话如何处理。
- 增加 MCP 连接检测、工具清单刷新及清晰的失败反馈。
- 改善批量导入状态和失败重试；按实际需求增加 PDF、Word 解析。
- 完善备份恢复和可追踪的运行错误记录。
- 如果进入多人使用阶段，加入登录、知识库与 Agent 权限隔离，以及独立凭据管理。
- 如果接入真实写入业务，为相应工具设计人工确认与审计流程。

### 验收标准

- 日常维护 Agent 和资料不需要修改数据库或源代码。
- 连接失效、导入失败和运行错误可定位、可重试。
- 如启用多人访问，验证用户不能读取其他用户未授权的资料和工具配置。
- 如接入业务写入，明确展示将执行的操作，并验证确认、取消与执行结果。

## 6. 第五阶段：主 Agent 调用副 Agent

### 首个场景

主 Agent 接收复合任务，将制度查询交给制度助理，将工时处理交给工时助理，再汇总结果。先验证有限、明确的分派流程。

### 工作内容

- 定义主 Agent 可以调用的副 Agent，以及各自输入和返回结果。
- 显示任务分派、执行状态、结果与失败原因。
- 限制调用次数、层级和超时，防止循环调用和成本失控。
- 副 Agent 继续遵守自己的工具白名单、知识库范围及审批要求。
- 主 Agent 汇总时保留副 Agent 返回的来源依据和操作状态。

### 验收标准

- 一个明确的复合任务能够完成分派、执行和汇总。
- 单个副 Agent 失败时，用户能看到失败部分，已成功的结果仍可使用。
- 调用链可以通过审计记录追踪。
- 主 Agent 不会绕过副 Agent 的知识库范围和人工审批要求。

## 7. LangChain 的引入原则

LangChain 是可选的实现工具，不单独作为功能目标。当前 Claude Agent SDK 已承担对话和工具调用，可以先在现有检索服务中增加 Embedding 与混合召回。

只有在文档加载器、向量存储适配或检索编排等具体环节确有收益时，再引入相应组件，并保留现有 API、来源数据和评估方式。引入前明确解决的问题、增加的依赖及替换成本。

## 8. 建议执行顺序

| 顺序 | 交付重点 | 完成后获得的能力 |
| --- | --- | --- |
| 1 | 当前版本收口、提交与备份 | 已有成果可恢复、可交接 |
| 2 | Embedding＋BM25 混合检索 | 改善同义表达和自然语言召回 |
| 3 | Notes 真实题集与回答评估 | 用实际问题验证质量变化 |
| 4 | Agent 管理及使用体验完善 | 减少日常维护成本，支持持续试用 |
| 5 | 有限场景的主副 Agent 协作 | 完成跨能力的复合任务 |

第二阶段开始前先建立少量同义词与精确查询对照题；第三阶段再扩充完整真实题集。这样可以边实现边验证效果。
