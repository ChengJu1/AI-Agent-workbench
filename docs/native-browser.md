# 本机专用浏览器与平台审批

2026-10-20：macOS 本机默认使用 `native_mcp`。其他环境默认保留 `legacy`；可通过 `WORKBENCH_BROWSER_PROVIDER` 明确选择。两种方案不共享正在运行的会话，切换后旧清单失效。

## 使用

安装固定版本的官方组件（Node.js 18+，本机已安装普通 Google Chrome）：

```sh
cd backend
.venv/bin/python scripts/install_browser_mcp.py
```

启动方式与原工作台相同。已有 Agent 的浏览器能力和工具名不变，不需要重新创建 Agent。打开「浏览器与登录」即可建立专用窗口；登录后点击「交回 Agent」，再读取和规划。

网站使用正常的浏览器网络，不再经后端逐请求代发、剥离 Cookie 或审批每个静态资源。接手计时只暂停 Agent 的读取和执行，不暂停网站网络。输入、上传、点击仍由工作台生成确认清单，核对网站、内容及附件版本后执行。

预览只在点击「预览此步」「查看当前页面」或「刷新画面」时截图；定时请求仅更新页面地址、执行状态和缓存画面，不定时截图或滚动。接手期间不读取 DOM、不截图。截图标明真实拍摄时间，不能将旧画面当作新回执。清单过期、失败或页面变化不阻止只读截图，但不展示未经核对的目标框，也不恢复清单的执行权限；历史清单按其原浏览器会话定位，不把目标画到另一窗口。

页面指纹比较语义内容：保留网址、正文、控件、字段值、选项、禁用/勾选状态及文件选择；忽略快照引用编号、焦点/光标标记和 CSS 类名。仅剔除 YAML 节点头里的观察属性，正文及字段中形似这些标记的文字仍参与比较。实际内容变化仍要求重新读取生成清单，不能借此重放原审批。

## 登录交接与任务续接

用户只接手登录、密码、验证码或必须本人处理的步骤。点击「交回并继续」会先交回浏览器控制，再在当前聊天发送一条可见续接消息；助手重新查询会话、读取页面，并继续准备填写和附件上传清单。该消息不清空输入框草稿，也不代表已登录或已批准业务操作。交回失败不触发模型回复，不自动重试。

每批浏览器审批成功后，工作台会发送续接消息，让助手核对结果并规划下一步；失败、取消及其他类型审批不自动续接。最终提交独立审批，不能与填写或上传混为一批。自动续接只规划和读取，不自动批准下一批，不重放已执行动作；页面刷新或重新进入历史会话也不触发续接。

browser_read 返回已有 tabs，可传 tab_index 选择当前会话的已有网页；about:blank 且只有一个原站网页时直接恢复该页，不创建新窗口，不关闭原页。存在多个候选时需明确选择，跨会话和不存在的标签均拒绝。标签摘要隐去 URL 查询参数和片段。页面无正文、仍加载、快照异常和待选标签分别返回 page_state；空页不生成可审批快照。网页格式无法解析时直接报告读取错误，不伪装为空 DOM。配置保留不证明登录或提交成功。

同一会话重复 browser_open 会复用当前页并提示请求地址不同，不再诱导模型关闭已登录填写页后重新导航。页面实际发生跨站跳转时，可用当前完整网址核对并复用，或明确选择已列出的网页标签；新的操作仍绑定实际目标站点、快照和审批。

浏览器管理增加“检查页面与标签”与已有标签选择，只读统计正文长度及控件数量。空页诊断仅返回文档状态、正文长度、iframe 数量和失败资源的域名/状态/网络错误码，不返回请求查询参数、正文或凭据。

页面 YAML 的 native_ref 与 elements.id 均可引用，但必须精确属于当前快照；审批统一保存平台 ID，不能借此接受任意选择器。

完整快照与所有元素引用保存在当前浏览器会话内存，不再只保留前 250 个控件。工具每次默认返回 12,000 字符和 80 个控件，同时给出全文/全部控件总量与下一页偏移。需要末尾字段或上传区时，调用 `browser_read(session_id, snapshot_id, query="上传")` 查找完整快照；继续分页使用同一 `snapshot_id` 及 `text_offset` / `element_offset`，可调整单页大小。分页与关键词查找不会重新读取 DOM、生成新快照或使前页引用失效；新读当前页面时省略 `snapshot_id`。新快照、接手/交回、执行消费后旧分页引用不可继续使用，不能跨会话读取缓存。

对于自身没有文字、子节点才包含提示的可点击 generic/div 上传容器，保留上游真实引用并从子节点提取提示；跨 iframe 的 `f1e…` 等引用同样保留。上传仍只使用获批会话附件的版本与哈希，经平台清单确认后执行。大页面返回不完整时先搜索或分页，不得以此要求用户手动选择文件。浏览器管理的正文/控件计数显示完整快照总量。

官方引用中的框架 div/span 控件不再被旧的 onclick/cursor 启发式规则提前拒绝；用户审阅具体目标后，由 Playwright 在执行时检查可操作性。工具报错不等于清单生成成功，必须有实际 pending_action.id。

公开搜索不发送个人资料；向用户选定的业务站点填写或上传资料仍需审阅确认。构建助手应区分这两个用途，避免同时生成“代办上传”与“禁止向任何第三方发送资料”的冲突规则。已有明确隐私限制不能由模型自行忽略。

## 会话、文件与隔离

- 每个对话一个官方 MCP stdio 进程和专用 Chrome 配置，最多同时四个窗口。同一对话复用页面，切换网站前关闭旧窗口；不同对话不能访问对方的会话 ID。
- 配置保存在 `backend/data/browsers/native-profiles/<对话哈希>/profile/`，与个人 Chrome 和此前 8088 实验配置分开。现有实验登录没有自动复制到正式会话。正式会话首次使用需登录，之后关闭窗口和后端重启会保留该配置；网站仍可能使登录过期。
- 后端重启会关闭窗口，需重新打开网页。不会恢复或重新执行旧审批清单，也不承诺窗口跨进程持续运行。
- 审批绑定 provider、会话、快照、页面指纹、时限和附件版本。手动接手、页面变化、撤销能力、文件变化或已使用的审批均不能继续执行。点击和上传作为一批最后一步，随后重新读取。
- 官方上游工具不直接暴露给模型。页面读取与指纹仅使用平台内置的观察函数；不开放任意代码执行、工具调用、浏览器存储导出或宿主文件路径。
- 上传只取当前对话中获批的附件版本。专用私有目录保存不可变副本，供浏览器延迟读取，直至窗口关闭后清理；不在选择文件后立即删除。进程异常退出可能留有私有副本，按本地敏感数据管理。
- 配置、登录状态、截图与错误附件均为本地敏感运行数据，已被 Git 忽略。没有账号级权限系统，当前方案是人工在场的本机个人工作区，不是可直接公开部署的多用户浏览器服务。服务器部署需要另外的执行和网络出口隔离。

## 结果如何解释

点击完成、文件选中、表单可读取都不代表业务提交成功。执行记录继续使用 `needs_verification`，需依据实际回执或后续状态查询核实。失败不自动重试，尤其不能直接重复点击提交。

官方工具也不能保证所有网站、SSO、验证码、自定义控件均可自动完成。无法核对的目标应重新读取或交由用户接手，不能猜测控件、跳过验证或放行全部上游工具。

## 回归与验收

`backend/tests/test_native_browser.py` 覆盖审批前不执行、旧清单与页面变更、跨对话、密码、文件版本、延迟上传文件生命周期、接手暂停、无定时截图、超时无重试、关闭窗口清理、上游危险工具未开放、截图接口授权。

`backend/tests/native_browser_validation_server.py` 在独立 8087 工作台使用合成资料验收填写、附件、独立提交确认、实际回执和台账。8088 原实验用于真实招聘页的只读验证，不连接正式 Agent。真实招聘申请没有作为自动化回归提交。
