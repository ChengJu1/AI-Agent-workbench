# AI Agent Workbench 工作进度

更新日期：2026-10-19

本文记录当前本地项目的实现状态。后续安排见 [下一步计划](./workbench-next-steps.md)。

## 1. 当前阶段

项目已经形成可演示、可试用的功能闭环：

> 创建 Agent → 配置 MCP 工具或绑定知识库 → 对话检索 → 查看引用原文 → 批量评估检索效果。

当前定位是面向团队协作场景的 AI 工作台原型，尚未完成面向多人使用的产品化能力。

主要技术组成：

- 前端：React、TypeScript、Vite。
- 后端：FastAPI、Claude Agent SDK。
- 模型接入：当前通过 DeepSeek 的 Anthropic 兼容接口调用模型。
- 数据存储：SQLite，关键词索引使用 FTS5。
- 工具接入：内置受控 CLI、stdio MCP，以及用户配置的 HTTP/SSE MCP 服务。
- 开发部署：支持本机运行及 Docker Compose。

## 3. 当前知识库与检索实现

### 文档切分

- 有标题的 Markdown 按标题块切分，采用 `A+B`、`B+C`、`C+D`，相邻片段重叠一个完整标题块。
- 保留章节路径、字符位置和原文行号。
- 无标题 Markdown 和 TXT 回退到字符切分：最多 800 字符，重叠 100 字符，优先在自然边界断开。
- 已有文档支持自动升级切分索引，保留文档内容版本及历史引用快照。

### 检索与去重

- 当前使用 SQLite FTS5 关键词匹配和 BM25 排序。
- 先取返回上限 3 倍的候选，再按同一文档、同一版本的原文区间合并重叠结果。
- 例如命中 `A+B` 和 `B+C` 后返回 `A+B+C`，重复的 B 只保留一次。
- 合并扩展上限为 4000 字符；已有单个长片段不截断。
- 页面、Agent 工具和批量评估共用同一检索实现。
- 页面显示候选数、去重后组数、返回组数和后端检索耗时；这些耗时不包含模型生成时间。

## 5. 尚未实现与当前边界

- 已有基于关键词检索的 RAG 问答，尚无 Embedding、向量检索、混合检索或 LangChain 集成。
- 知识库检索是否触发、查询词如何选择仍由模型决定，没有每轮强制检索。
- 引用可以核验来源，但不等于回答结论已经通过事实检查。
- 尚无主 Agent 调用副 Agent 的任务编排。
- 自定义 Skill 当前是每轮注入的文本规则，不包含目录附件、脚本执行、自动发现、项目级绑定或版本回滚。
- 文档拆任务、代码巡检和随项目变化的只读 Checklist 尚未实现；需求拆解 Skill 示例只进行对话中的文本整理。
- 自定义 Agent 支持创建和使用，通用编辑、删除能力尚未完成；知识库绑定可以单独修改。
- 尚无账号登录和用户级权限隔离，Agent 与知识库在当前工作台共享。
- MCP 认证信息保存在当前数据库配置中，尚未形成独立凭据管理能力。
- 通用远程 MCP 工具尚未接入与工时助理相同的人工审批流程。
- 工时、日程与企业业务数据仍用于演示，尚未连接真实企业系统。
- 文档上传主要支持 MD/TXT，尚无通用 PDF、Word、图片解析和异步入库任务。
