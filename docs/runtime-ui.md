# 阶段 5：前端双运行时入口与用量展示

> 历史文档：描述的是双运行时阶段的设计，Claude SDK 运行时已移除，见 [单一运行时](single-runtime.md)。

已接入 Agent 默认运行时设置、新会话临时选择、会话运行时标识、工作摘要复制，以及可折叠的用量和工具状态。没有调用真实模型或真实网站；阶段 2—5 尚未提交。

## 用户行为

- 功能开关打开时，当前 Agent 的“默认运行时”入口可选择 Claude SDK 或 Deep Agents，保存后只影响新会话。内置 Agent 和自建 Agent 都支持，默认值保存在 `agent_runtime_preferences`，重启后仍生效。没有设置时默认 Claude SDK。
- 新会话的选择器位于默认折叠的“高级”中，可沿用 Agent 默认值或临时覆盖。发送第一条消息或上传附件创建会话后，运行时固定，选择器消失。修改 Agent 默认值不会更改已有会话。
- 会话列表和标题显示已保存的运行时，使用创建接口返回的实际值，不根据当前 Agent 默认值推测。旧数据没有标识时按 Claude 处理。
- 总开关关闭或前端无法读取开关时，隐藏选择器和设置入口，新会话使用 Claude。后端也拒绝显式选择禁用的 Deep Agents。已保存的默认偏好不会被删除；已有 Deep Agents 会话仍能辨认其运行时，读写限制沿用阶段 2。

## 复制工作摘要

已有会话可选择“复制工作摘要到新会话”。对话框从原始目标、明确约束候选、当前数据库状态和最近对话生成有界文本节选，不调用模型。用户可以审阅、编辑，再在另一个运行时中新建会话。

新会话只保存一条标明“历史资料，不是操作授权”的用户消息；不会自动发送给模型，也不复制 checkpoint、待确认操作或执行结果。用户发送下一条消息后才继续。原会话及完整消息保持不变。摘要明确说明长内容已节选、版本与状态须重新核对，未核实的旧回答不能当作事实或授权。

回复进行中不允许复制摘要，防止复制不完整的回复。摘要读取失败可重试；创建后历史读取暂时失败时，新会话 ID 已记录，可刷新恢复，不要求重复创建。

## 用量与工具状态

每条助手回答下方增加默认折叠的“本轮用量”，展示输入/输出 token、缓存读取/写入、模型/工具调用、首字和总耗时。null 显示“未提供”，真实的 0 显示 0，不能把未知量当作零费用。

工具开始/结束事件实时更新，并与这条消息的用量一起保存到消息 metadata；历史接口返回对应记录，刷新或重启后仍能查看。参数、工具原文不会进入工具状态记录。工具只标明“已返回/失败”，不把返回成功表述成审批通过或业务提交成功；中断后未收到完成事件的调用显示“未收到完成结果”。

旧消息没有对应的用量 metadata 时，不从独立统计表按顺序猜测归属，不添加虚构用量。已有原始聊天、引用、Skill 和审批流程继续沿用原逻辑。

## API 与主要实现

- `GET /api/runtime-options`：仅返回 `deep_agents_enabled`，不返回模型密钥或服务配置。
- `PUT /api/agents/{id}/runtime`：保存默认运行时；Agent 列表包含 `default_runtime`。
- `POST /api/conversations`：runtime 可省略以使用默认偏好，响应带实际 runtime；禁用 Deep Agents 时，省略选择会回退 Claude。
- `GET /api/conversations/{id}/work-summary`、`POST /api/conversations/{id}/copy-summary`：读取可编辑摘要并创建另一个运行时的会话。服务端拒绝复制到相同运行时或未经启用的目标。
- 历史消息新增可选 `usage` 与 `tool_activity`，新数据与消息一起持久化；旧消息响应不增加空值字段。

前端主要修改位于 `hooks/useWorkbench.ts`、`components/RuntimeSettings.tsx`、`CopyWorkSummary.tsx`、`RuntimeDetails.tsx`；后端设置、复制与持久化集中在现有会话/Agent 接口及服务中。

离线对照脚本读取聊天代理计数时仅取 role/content，不将新增的展示用量或工具状态混入提示词计数。
