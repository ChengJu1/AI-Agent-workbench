# Agent 绑定知识库与检索工具

Agent 可以绑定当前工作台中的知识库。后端每轮对话读取最新绑定，为它注册只读检索工具，返回已有的 BM25 检索结果和原文来源。

## 页面使用

1. 在“知识库”中建立文档库并上传资料。已有演示资料时可直接使用。
2. 创建 Agent：填写名称、用途和提示词，在“可查询的知识库”中勾选资料库，点击“创建并使用”。可以只选知识库，无需配置外部 MCP 服务。
3. 已有 Agent：在顶部选中 Agent，点击“绑定知识库”，选择资料库并保存。内置和自定义 Agent 都支持，最多绑定 10 个库。
4. 在聊天中输入“请检索 GPU 申请制度”。模型可使用知识库工具检索，并根据返回的原文继续回复。
5. 重新打开“绑定知识库”可以核对已保存的选择。取消全部勾选并保存可解除绑定。

绑定更新从下一轮对话生效；当前正在生成的工具配置不会自动增加新库，但每次实际调用都会重新检查当前绑定。解除绑定后，旧工具不能继续读取该库。历史对话中的资料和已经返回的内容不会被清除，需要全新上下文时请新建对话。

## 工具行为

- SDK 工具名称：`mcp__workbench_knowledge__search_knowledge`。
- 参数：`knowledge_base_id`、`query`，可选 `limit`（默认 5，范围 1–20）。
- 工具说明列出当前绑定库的名称与 ID，参数 schema 将 ID 限制为该轮已绑定的范围。
- 关键词处理、文档分段和 BM25 排序复用管理页面的检索服务，不维护另一套索引。
- 结果包含知识库 ID、名称、匹配片段，以及文件名、文档版本、章节、行号和字符位置。无匹配时返回空 `matches`。
- 每次实际执行记录一条 `tool_type: "knowledge"` 审计，包含查询、结果或失败说明；不会重复进入远程 MCP 审计。
- 未绑定的 Agent 不注册该工具。删除知识库会清理其绑定，下轮对话不再注册已删除库。
- 系统提示词指导模型先查资料，但工具是否调用、使用什么关键词仍由模型决定。回答引用组件和原文快照已实现，见 [带引用的知识库问答](./knowledge-answers.md)；每轮强制检索、向量检索和混合检索尚未实现。

调用知识库工具的对话仍需要现有模型配置。匹配片段会传给该模型作为上下文；整个知识库不会预先放进系统提示词。

## API

创建 Agent 的 `POST /api/agents` 新增可选 `knowledge_base_ids`，`tools` 可省略。至少配置一个知识库或 MCP 工具：

```json
{
  "name": "知识库助理",
  "description": "查阅团队资料",
  "system_prompt": "涉及团队制度时先检索资料；未找到时明确说明。",
  "knowledge_base_ids": ["已有知识库ID"],
  "tools": []
}
```

- `GET /api/agents/{agent_id}/knowledge-bases`：读取已绑定知识库，返回知识库信息数组。
- `PUT /api/agents/{agent_id}/knowledge-bases`：整体替换绑定，请求为 `{"knowledge_base_ids": ["知识库ID"]}`，成功返回更新后的知识库信息数组。传空数组解除全部绑定。

不存在的 Agent 或知识库返回 404。重复、超限或无效参数返回 422，更新失败保留原绑定。创建 Agent 与保存绑定在同一事务中完成。已有远程 MCP 连接名与保留名称 `workbench_knowledge` 冲突时，绑定返回 409；新建连接禁止使用该名称。

绑定保存在 SQLite 的 `agent_knowledge_bases` 表中，重启保留。它限制当前 Agent 工具的查询范围，工作台尚未实现账号级权限隔离。

## 验证范围

自动化测试覆盖只绑定知识库创建 Agent、内置 Agent 的绑定修改与恢复、非法更新回滚、删除清理、真实 SDK MCP 协议调用、跨库拒绝、运行中解除绑定、空结果和错误信息处理。对话接口测试使用模型替身，并通过实际 SDK 工具和 SQLite 索引完成检索。

本次完整回归：后端 72 项、前端 19 项测试通过，前端生产构建通过。自动化验证不替代真实模型对工具选择行为的验证。

本机页面联调已验证：创建仅绑定“演示知识库 · 团队协作”的“知识库检索助理”，重新打开绑定界面并保存，再发送“请检索 GPU，申请两张 GPU 需要谁审批？”。当前配置的真实模型调用 `search_knowledge` 成功，依据原文回答“项目负责人和资源管理员共同审批”；SQLite 审计记录为 `knowledge / search_knowledge / success`。此结果验证了该条对话的调用链路，不代表所有问题都能正确选择工具或命中资料。
