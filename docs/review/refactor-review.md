## 本轮复现并修复的问题

| 问题 | 触发与影响 | 改动 |
| --- | --- | --- |
| SDK 失败结果被当作成功 | SDK 通过 `ResultMessage` 报告错误或轮数耗尽时，原流程忽略结果，仍发送 `done` | 检查结果类型和错误标记，向页面发送安全的错误说明，保留部分回复 |
| 模型失败后遗漏审批卡片 | 工具已经创建待确认操作，后续模型调用失败，审批事件没有送到页面 | 在报告模型错误前发送本轮已创建的审批操作 |
| 创建操作和审计分别提交 | 审批操作落库成功、审计写入失败时，出现没有对应创建审计的操作 | 在同一事务中创建操作和审计；失败时一起回滚 |
| SDK 工具列表超出 Manifest | Agent 只配置查询操作时，SDK Server 仍登记全部三个工时操作 | 按 Manifest 中 CLI 工具的 action 注册，工具列表与允许列表一致 |
| 断连后会话未释放 | 响应头发送失败，或在部分文本发送后断连，异步生成器没有及时关闭 | 响应发送结束时关闭流，并在外层兜底释放请求占用 |
| 清理请求的时机和身份不明确 | 旧响应结束后的清理可能影响下一轮；旧版 ASGI 在子任务中发送流 | 用每次请求独立的标识释放占用，并在发送流的原任务中关闭生成器 |

工时工具的三个重复注册流程改为统一定义和注册函数，代码由 259 行缩减为 108 行。提交工具仍只创建待确认操作，实际执行由审批服务完成。

## 当前边界

- 同一会话的并发控制在进程内生效，当前适用于单进程开发服务。多 worker 部署需要共享的会话互斥机制。
- 工具已执行、结果保存失败时，操作保留为 `executing` 并拒绝重复执行。恢复需要核对实际提交结果，当前没有自动对账流程。
- 数据库聊天记录和 SDK 会话文件分别持久化，SDK 上下文恢复仍依赖对应会话文件。
- 自动化验证不覆盖真实模型服务、真实企业工时系统或浏览器完整交互；工时数据仍为演示数据。
