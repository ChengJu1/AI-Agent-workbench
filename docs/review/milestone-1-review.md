# 里程碑 1 复核（偏口语版）

## 结论

**里程碑 1 当前不算完全通过。**

页面和后端主链路是通的，能发消息、能看到连续回复；但“会话能持久保留”和“出错时能一眼看懂是什么问题”这两块还没打通，按正式验收标准还差这两个关键缺口。

## 对照验收项

- 本地能启动前后端：✅
- 页面有工时助理这个入口：⚠️ 显示为“工时助手”，和里程碑文档里叫法不一致。
- 发消息后能返回回复：✅
- 回复是分段显示：✅
- 同一会话可以继续追问：✅（在页面不刷新的前提下）
- 启动文档和演示步骤完整：✅
- 会话可恢复（含刷新后或重启后）：⚠️

## 缺口清单（都带可复现路径）

### 1. 重启后端会把历史会话清掉

**复现路径**
1. 打开页面并发送一条消息，确认有返回。
2. 记下当前 `conversationId`（可在控制台看到 `POST /api/conversations` 的返回值）。
3. 停掉后端再按原命令启动：`uvicorn app.main:app --port 8000`。
4. 再用同一个 `conversationId` 调接口 `POST /api/conversations/{id}/messages/stream`。

**现象**
- 接口直接报 404，旧会话不存在。

**原因**
- 会话存到 `backend/app/services/conversation_store.py` 里的内存字典里，服务重启后立刻消失。

**影响**
- 导师或你自己复测时，重启一次就丢上下文，不算“可复现的稳定演示”。

### 2. 刷新网页后，消息列表会空掉

**复现路径**
1. 连续问两三句，页面里出现一段聊天记录。
2. 不发新消息，直接刷新浏览器。

**现象**
- 聊天区变成空白，不再显示刚才的对话。

**原因**
- 对话列表只保存在前端内存里，且没有提供“按会话读消息”的接口。

**影响**
- 看起来像重新开了一次对话，体验不连续。

### 3. 后端异常时报错提示不够清楚

**复现路径**
1. 后端已起，但把 `backend/.env` 的 `ANTHROPIC_API_KEY` 清空或写错。
2. 页面点“发送”。
3. 或者关闭后端后刷新页面再看。

**现象**
- 页面不会稳定给出“后端没启动/密钥错误”这类一句话判断。

**原因**
- `frontend/src/api.ts` 在 `fetchAgents`、`createConversation` 中先拿结果再读 `json()`，没有先按 HTTP 状态码分支；`streamMessage` 的错误也直接丢给用户，不做一次翻译。

**影响**
- 排障慢，第一次演示时容易以为是前端问题，实际是接口配置问题。

### 4. 文档里要求的 Agent 名字和页面展示不一致

**复现路径**
1. 打开页面观察左上角的 Agent 下拉框。

**现象**
- 页面显示“工时助手”，与里程碑要求“工时助理”文案不一致。

**原因**
- `backend/app/agents.py` 里把名字写成了另一种叫法。

**影响**
- 属于展示一致性问题，会让验收人员对照文档时多一次疑问。

## 建议

如果按今天这版的检查口径，建议验收结论为：**未通过（有 2 个功能缺口）**。先修：
- 会话要落盘（文件或 SQLite）
- 错误状态要给明确中文提示
